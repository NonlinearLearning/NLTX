## 2. 核心模型

### 2.1 Entity 是身份与组件关联

一个运行时 Entity 由有效实例身份及附着到该实例的组件集合表达。能力和持续状态属于
组件，行为属于围绕这些组件执行的领域系统。

```text
实体实例身份
  ├─ 身份/生命周期记录
  ├─ 位置、运动与碰撞等组件（具有相应能力时）
  ├─ 生命、物品、交互或其他领域组件（按实际组合）
  └─ 指向其他实体的关系组件

系统通过实体引用和所需组件访问状态；原型/创建方法提供初始组合。
```

约束如下：

1. `Player`、`Npc`、`Projectile` 等分类通过实际领域组件、能力组合和创建定义表达。
   不建立继承树或固定大对象，把实体类别变成所有状态的长期容器。
2. 共享能力组件可关联到不同类别的实体；增加一种使用者，不应要求复制该组件或修改
   一个收容全部实体字段的基础类。
3. 是否需要独立 Entity，依据独立生命周期、能力组合或跨实体引用需求决定。瓦片值、
   槽位、采样记录等批量数据可以留在领域组件或专用存储内，不强制逐项实体化。
4. 身份登记和组件关联属于 ECS 运行时能力；身份 Registry 不承载生命、运动、背包等
   领域状态，也不负责文件 I/O、序列化或协议处理。

### 2.2 必须区分的对象

| 对象 | 职责 | 有效范围 |
| --- | --- | --- |
| 实例身份根 | 标识一次权威实体实例；本仓库沿用 `EntityUuid` | 该实例生命周期 |
| 运行时句柄 | 在所属运行时快速解析实例及组件 | 指定世界/运行时及其有效期 |
| 网络/兼容投影 | 协议、连接或旧槽位到实例的映射 | 相应边界作用域 |
| 持久化身份 | 关联跨加载保留的业务对象 | 存档或业务对象生命周期 |
| Component | 某一实体实例的能力、状态或关系 | 附着期间及规定的生命周期阶段 |
| Prototype/Definition | 可复用的初始组件组合和默认值 | 定义版本；不等于运行时实例 |
| 类型化实体视图 | 携带实体引用及当前需要的组件 | 当前访问协议允许的有效期 |

原型 ID、NPC 类型 ID、物品定义 ID、账户 ID 和实例身份必须有可区分的类型和语义。
相同原型创建出的两个实体仍是两个独立实例。

## 3. 身份、作用域与槽位

### 3.1 身份登记

- 实例身份根由权威创建/提交流程生成并登记；客户端、原型、协议和存档数据经各自边界
  解析，不能覆盖根身份。具体唯一性和投影契约以现有身份决策为准。
- 高频组件查找可以使用局部句柄或内部索引；它们是查找机制，不是第二套可互相覆盖的
  权威身份。根身份、句柄和边界投影的映射必须随生命周期登记和清理。
- 标识值格式合法、实体存在、实体正在终止、实体可参与当前阶段，是不同判断；访问
  协议必须检查本次操作需要的条件。
- 实际销毁后重新创建的实例取得新根身份。仅改变生命状态、控制者或能力组合，且实例
  本身继续存在时，不重新分配根身份。

### 3.2 槽位复用与多世界

- 槽位可复用时，句柄必须携带 generation 或采用等价的失效判定；旧引用不能解析到
  新占用同一槽位的实体。耗尽、世界重置和会话重建的失效规则必须明确。
- ID、句柄和组件访问属于明确的世界/运行时作用域。跨世界传递必须显式解析作用域，
  不能根据相同整数、槽位或原型名推断是同一实体。
- 按 Player、NPC、Projectile 分开的容量表、扫描顺序和兼容索引可以保留；它们应能
  解析到相应实例及其组件，不各自引入与根身份竞争的实体定义。
- 实例 ID 若从可复用槽位计算，必须证明其仍区分不同实例；只拼接世界 ID 和槽位不足以
  区分同一世界内的多次槽位占用。

## 4. 组件关联与权威存储

### 4.1 关联不变量

ECS 运行时必须提供“指定实体上的指定组件”和“符合指定组件组合的实体”的可验证访问
机制。可以由现有框架、类型化组件表或其他等价实现提供，不要求自建框架。

- 每份可变组件实例只附着到一个实体；创建多个实体时不共享可变组件对象、数组或集合。
  不可变定义可以共享，实例状态必须独立。
- 同一实体上的同一组件注册身份只有一份权威状态；实体侧访问、类型查询和辅助索引必须
  指向同一份状态。替换、移除与重加组件必须更新关联和失效信息。
- 抽象组件族、端别实现和查询别名以实际注册契约为准；C# 继承关系不自动保证基类查询
  能命中具体组件。别名不能形成第二份权威状态。
- 派生快照、网络 DTO、存档 DTO、只读投影和缓存允许复制数据，但必须标明来源、捕获
  边界和失效规则，不能与组件并列接受权威写入。
- 各索引、事件订阅和缓存必须明确在组件移除、实体删除和世界卸载时如何清理。

### 4.2 组件与系统的责任

组件负责表达状态；领域系统负责维护行为和不变量；运行时存储负责关联和生命周期。
这三项责任不能因某个类型名包含 `Entity` 或 `System` 而合并。

一个组件可以由多个系统按公开协议协作访问。每项不变量应有明确的提交责任和顺序，
不以“一组件只允许一个 System”代替协议设计。系统可以同时提供查询、规则判断、修改
方法和事件处理；不要求所有系统无状态，也不要求 Shared 层纯函数化。

位置与速度等跨类别能力只保留明确的权威表示。历史 `whoAmI`、坐标镜像及平台对象可以
由兼容层投影，写入方向和提交点必须确定，避免两套状态各自推进再互相覆盖。
公共位置名称沿用现有 `LocationComponent` 决策；采用参考项目的层级坐标时，必须另行
评估坐标语义，不能直接照搬 `TransformComponent` 名称与状态。

## 5. 原型、创建与实例化

### 5.1 定义组合

原型、Bundle、创建方法或定义目录只描述初始能力组合和默认值。采用何种配置格式由项目
实际需求决定。

- 原型继承用于复用和覆盖组件定义，不引入运行时 `PlayerEntity -> NpcEntity` 分类树。
- 默认组合只包含该类实例真正需要的能力；可选能力通过实际组合或明确的启用规则表达。
  使用固定布局时，也必须能区分能力不存在、能力关闭和状态为默认值。
- 可变默认值实例化时复制或独立构造；运行时写入不得污染原型或其他实例。
- 原型中的实体关系必须在实例化或加载上下文解析；配置不能保存上一次运行的局部句柄。
- 组件注册键和定义版本的校验、迁移及命名遵循既有组件命名约束，不另建猜测式字符串表。

### 5.2 创建提交

创建流程必须说明：身份与句柄分配、组件实例化、必要关联建立、初始化/启动、对正常
模拟可见的边界，以及失败清理。初始化事件可以访问构建中的实体，但必须遵守该阶段的
可用状态协议；不能把已分配身份当作已经完成所有初始化。

必要组件、关系或定义校验失败时，清理已分配的组件、映射和资源，或返回明确的未完成
状态并阻止其进入正常更新。此要求不强制创建数据库事务或两阶段提交类型。

创建或运行后动态添加组件时，由统一的运行时关联入口补齐其适用生命周期。领域代码不能
仅向某个集合塞入对象，就假定索引、启动、订阅和网络登记也已完成。

## 6. 生命周期与结构变化

### 6.1 分开建模三种生命周期

| 生命周期 | 典型变化 | 组织要求 |
| --- | --- | --- |
| 实体运行时生命周期 | 分配、初始化、启动、终止、删除 | 运行时管理实例有效性与清理 |
| 组件生命周期 | 添加、初始化、启动、停止、移除 | 与实体当前阶段协调；更新关联和订阅 |
| 玩法生命周期 | 生存、死亡、休眠、复活、消耗 | 由对应领域状态和系统表达 |

怪物死亡不等于实体删除：尸体、掉落、复活或控制转移可能继续使用同一实体。
移除某项能力也不等于删除实体。暂停和休眠应明确影响哪些系统、计时和查询；相关系统、
计时和缓存按同一协议处理，允许继续推进的部分需明确。

需要地图/世界准备完成后才能执行的初始化，应声明独立的准备条件；不要把“组件已启动”
等同于“地图资源已经可用”。不强制照搬 SS14 的生命周期枚举或所有事件名称。

### 6.2 同步与延迟操作

- 添加、移除、替换和删除都通过受控运行时入口执行；说明何时改变查询结果、何时发出
  生命周期通知，以及通知中还允许访问哪些状态。
- 同步操作和排队操作分开定义。排队删除只代表请求已经登记；在实际处理前，查询或
  引用可能仍能看到该实体，调用方应根据操作协议检查“正在终止/已请求删除”等状态。
- 遍历中是否能结构性修改，以存储和迭代器的实际契约为准。需要延迟时使用已定义的
  提交点；支持安全同步修改时可以直接操作，不强制所有修改排队。
- 调用可能触发事件、替换组件或删除实体的协作者后，继续使用先前组件引用必须重新
  验证有效性，或有保证其有效的明确访问协议。
- 删除流程覆盖身份投影、关系、索引、订阅和资源释放；重复请求及清理重入不得使旧
  引用重新有效，也不得重复释放资源。组件或实体终止期间不得无协议地重新挂载状态。

具体通知顺序由实际运行时及领域依赖决定，不按文件顺序、类声明顺序或其他框架样例推断。

## 7. 系统访问与类型化视图

### 7.1 按所需能力访问

系统通过实体引用解析所需组件，或查询具有指定组件组合的实体。普通计算可以接受显式
传入的组件值或快照；这种计算不因此成为实体集合查询，也不能替代运行时组件关联。

- API 描述实际需要的组件和前置条件，避免为了读取位置而依赖完整 `RuntimeNpcEntity`。
- 必需组件缺失、可选组件缺失、实体失效和实体暂停采用可区分的契约；查询应明确是否
  包含暂停、终止中或待删除实体。
- 组件存在与组件已经启动、正在停止或等待移除分别判断。延迟移除时仍能解析到组件，
  不代表它仍可参与正常模拟；调用方按本次操作的生命周期前置条件处理。
- 类型化实体视图可以携带身份和已解析组件，减少重复查找。它不创建新实例、不复制
  权威状态、不固定实体全部能力，也不因为其泛型参数而取得长期有效性。
- 视图中携带的组件必须属于该实体，且在当前阶段有效。跨帧、异步任务、存档和网络
  消息保留可解析的身份或快照，不依赖长期持有的组件对象引用。
- 查询结果、组件借用和迭代器声明有效期、结构变化失效条件及并发访问规则；可写组件
  查询不能被只读接口名误包装成不可变快照。

### 7.2 协作与副作用

已有能力 owner 的操作可以直接调用系统 API；需要扩展参与或通知时使用已有事件协议。
事件的取消、重入、状态修改和顺序必须取证，不假设事件天然异步或无副作用。

计算、状态提交、Dirty/复制通知及外部效果遵循
[副作用隔离规范](../约束/非函数式编码副作用隔离规范.md)。不因为使用 ECS，就为每个
读写操作创建独立 Query/Command 类型、消息总线或全局阶段。

## 8. 跨实体关系

- 拥有、控制、牵引、装备、目标、空间父子等关系使用可解析的实例身份或受作用域保护的
  句柄，不通过嵌套完整实体对象表达长期拥有关系。
- 空间父子、玩家会话、背包容纳、战斗目标和玩法归属是不同关系；分别使用有语义的
  组件和领域 API。不得为省字段把它们合并为一个通用 `Parent`。
- 双向关系、反向索引和派生标记明确提交责任。例如开始牵引要协调双方引用及活跃标记，
  结束时按同一协议清理，不能只修改一边。
- 目标销毁、组件移除、控制转移及世界卸载时，明确采用断开、重定向、联动删除或其他
  领域规则。悬空引用解析失败必须显式处理，不能自动指向同槽位的新实体。
- 空间层级等确有无环要求的关系检查环；其他关系按领域不变量判断，不把所有关系图或
  系统调用图强行规定为树或 DAG。

## 9. 网络、预测与持久化

服务器权威身份和状态、客户端局部句柄、预测实例及复制标识必须分开。共享代码可以处理
组件状态和预测逻辑，最终权威性由真实提交协议决定。

- 网络消息传递该协议规定的投影及数据，由边界适配器解析到实体，再交给领域 API 校验
  和提交；客户端给出的槽位或 ID 不能直接成为权威实体引用。
- 组件是否复制、哪些字段复制和谁能看到，由实际网络契约决定；不是每个组件或字段都
  自动复制，也不是每个复制字段都能由客户端写入。
- 网络状态反序列化、预测恢复和重放必须与组件关联、生命周期和事件效果协调；新的
  实现应说明重复应用及过期实体引用的处理方式。
- 保存捕获领域快照，通过应用 DTO 和存储端口传递；加载将持久化身份关联到新实例。
  不保存运行时组件对象或局部句柄，不让 Codec 自行查找、创建或改写权威实体。

文件格式、协议包和平台资源的分层细节使用既有架构约束，本文不引入另一套跨层规则。

## 10. 既有聚合对象的迁移约束

现有 `ProjectileEntityState`、`RuntimeNpcEntity`、`RuntimePlayerEntity` 及分类槽位表是需要
逐路径评估的既有实现，不能仅因本文件新增就直接删除。判断聚合对象时检查它是初始
组合、临时视图、快照、兼容边界，还是长期拥有并推进全部状态的运行时容器。

| 既有形态 | 目标处理 |
| --- | --- |
| 固定实体类长期拥有各能力组件 | 将权威组件纳入实体关联；按能力逐步切换访问 |
| 创建方法集中构造初始组件 | 保留为创建组合，明确提交与失败边界 |
| 仅携带实体及所需组件的访问对象 | 可保留为类型化视图，声明有效期 |
| Player/NPC/Projectile 分类槽位 | 可保留容量、顺序和兼容用途；统一身份映射 |
| 存档状态、网络数据或诊断快照 | 保留为边界数据，按对应架构约束隔离 |

迁移前记录权威状态、调用者、顺序、生命周期与兼容身份；迁移后验证实际模拟入口。
过渡期只保留一个写入源，新旧对象不能各自维护一份可写位置、生命或身份再互相同步。
局部变量复制组件值后提交，是否符合要求由实际存储/借用协议判断，不机械视为双重状态。

`WorldStorageRoot` 的名称或目录本身不证明职责错误。它目前承载的运行时领域存储，只有
在引入文件/平台依赖或重复权威状态时才触及相应边界问题；需要重命名或迁移时另行记录。

兼容例外记录适用范围、当前权威写入源、保留原因、验证方式和退出条件。源码中的
