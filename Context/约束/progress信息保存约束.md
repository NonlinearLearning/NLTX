# progress 信息保存约束

本文件是 `Context/progress.md` 保存口径的权威正文。新增、改写、降级或清理 progress 条目，
或判断某段信息该不该写进 progress 前，完整阅读。文件落位规则见
[项目文件组织设计约束](../架构设计/项目文件组织设计约束.md)。

## 1. 职责边界

`Context/progress.md` 是每会话开工必读的当前上下文卡片，只回答“现在要知道什么”，
不承担变更记录职能。

| 允许保存 | 不允许保存 |
| --- | --- |
| 当前基线：活动项目、目录布局、运行入口 | 根因分析、方案取舍、源码行号引用 |
| 未闭合事项与其判定条件 | 落地清单：改了哪些类、哪个常量、哪个参数 |
| 技术债与跨轮遗留 | 验证证据：命令、退出码、PASS 数、日志路径 |
| 影响后续工作的环境事件 | 与 CR / 计划 / 审计正文重复的段落 |
| 轮次索引：日期 + 结论 + 链接 | 逐文件、逐字段的实现细节 |

判定口径：一段信息在 `docs/cr/`、`docs/plans/`、`docs/reviews/audits/` 里是否已有 canonical
位置。有，只留链接；没有，才写成条目，并为它补一份记录。

## 2. 条目粒度

轮次条目固定三档，按“有没有未闭合项”选择，不按作者偏好选择。

L0，已关闭轮次，一行：

```markdown
- 11-06 服务器运算系统引入 → [审计](../../docs/reviews/audits/2026-11-06-server-systems-introduction.md)
```

L1，无未闭合项的新轮次，一行加粗：

```markdown
- **2026-11-22 项目文件组织从 ECS 约束拆出**：仓库与项目层落位规则独立成文 → [CR](../../docs/cr/CR-2026-11-22-project-file-organization-split.md)
```

L2，有未闭合项的新轮次，两行：

```markdown
- **2026-11-22 NPC 同步出站优先级隔离**：出站按 realtime / normal 分道、队列与配额独立，Tick 内投影与 Tile drain 有界
  - 未闭合：待最新客户端实测抖动；Realtime 配额与 Tile 限流为保守默认值 → [CR](../../docs/cr/CR-2026-11-22-npc-sync-outbound-priority.md)
```

L2 的结构固定为：第一行 `- **YYYY-MM-DD 主题**：做了什么`，第二行
`  - 未闭合：判定条件 → 记录链接`。链接并入第二行行尾，不独占一行；无未闭合时链接并入
第一行行尾（即 L1）。

以上示例的链接按本文件位置书写；同样的条目写进 `Context/progress.md` 时，前缀改用 `../`。

## 3. 字段规则

- **主题**：动宾短语，说明这轮改了什么领域，不带路径。
- **做了什么**：写机制或行为层面的变化，不写实现载体。禁止罗列文件名、类型名、常量与参数值。
- **未闭合**：必须写成可判定的关闭条件，含“谁来验、怎么算过”。不能写成“后续观察”“继续优化”
  这类永远关不掉的句子。
- **链接**：指向该轮的 canonical 记录，一轮一个，不并列多个文档。

| 字段 | 合格 | 不合格 |
| --- | --- | --- |
| 做了什么 | 出站按 realtime / normal 分道、队列与配额独立 | `CommunicationOutboundDeliveryPump` 拆两条 worker、`PacketTcpConnection` 新增 128 KB / 32 帧 |
| 未闭合 | 待最新客户端实测抖动是否消失 | 后续观察效果 |
| 未闭合 | 13/13 验证通过前不得标记完成 | 测试待补 |

## 4. 生命周期

```text
新轮次 → L2（2 行）
  ├─ 未闭合关闭 → 删除该行并降为 L0（1 行），移入「更早轮次」
  └─ 超过 8 轮仍未关闭 → 未闭合项移入「长期未闭合」并标注起始日期，该轮降为 L0
```

「长期未闭合」按事项记录，不按轮次；同一事项只出现一次，关闭后整行删除。

## 5. 全文结构

顺序固定，不增删段落：

1. `## 长期未闭合`：按事项，带起始日期；
2. `## 技术债`：跨轮遗留，不属于某一轮；
3. `## 基线`：活动项目、目录布局、运行入口、受保护目录；
4. `## 工作区事件`：影响后续判断的环境事实，闭合后删除；
5. `## 最近轮次`：最多 8 条 L2，单一倒序；
6. `## 更早轮次`：L0 一行式；
7. `## 历史`：一句说明更早内容去哪找。

同一轮在全文件只出现一次。「最近轮次」与「长期未闭合」「技术债」之间不得重复同一条状态。

## 6. 上限与自检

入口上限 **70 行 / 6 KB**。超限时先按第 4 节降级最旧轮次，仍超限则把最旧的未闭合项并入
「长期未闭合」。

写入后自查：

- [ ] 每轮条目不超过 2 行，链接没有独占行；
- [ ] 「做了什么」里没有文件名、类型名、常量值；
- [ ] 每条未闭合都能判定“怎样算关闭”；
- [ ] 全文行数与字节数在上限内；
- [ ] 所有相对链接可解析；
- [ ] 时间线为单一倒序，没有重复轮次。

## 7. 与其它文档的关系

- 落地清单、验证证据、回滚方式归 `docs/cr/CR-YYYY-MM-DD-主题.md`。
- 批次状态与未完成项归 `docs/plans/`；能力边界与证据范围归 `docs/reviews/audits/`。
- 本约束与 [开发协作与变更约束](开发协作与变更约束.md) 冲突时，以本文件的进度记录规则为准。
