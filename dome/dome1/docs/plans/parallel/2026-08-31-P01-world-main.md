# P01 World and Main Field Closure Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将 Main/World 中尚未独立核对的服务器字段和派生属性拆为 declaration-level field
cards，并确定每项的唯一 World owner。

**Architecture:** World metadata、规则、时钟、天气、进度、Tile definition registry 和
WorldObjects 入口彼此分离。静态表进入独立 immutable registry；派生 property 进入 query；
transient display projection 不进入 Simulation。

**Tech Stack:** C# immutable registries and World query policies, documented by this Markdown
field-card plan. No test files are added; build is attempted only as a compile sanity check.

  `Manager` type.

## 5. Component design

| Component/query | Owns | Does not own |
| --- | --- | --- |
| `WorldMetadata` | `WorldId`、name、dimensions、bounds、spawn、seed/version metadata | client view、packet field、file handle |
| `WorldBoundaryPolicy` | `offLimitBorderTiles` 和边界 predicate | render viewport、wire bounds |
| `DungeonSpawnPoint` | dungeon spawn X/Y、`-1/-1` unset、non-negative validation | Dungeon bounds、NPC wire target |
| `WorldRuleState` | GameMode、difficulty、secret-seed/generation rule inputs | UI text、network mode |
| `WorldRuleQuery` | Journey/Expert/Master 等 derived result | second mutable cache、packet flags |
| `WorldSurfacePolicy` | surface threshold query | terrain renderer |
| `WorldWeatherState` | rain amount/time/target、weather transition input | cloud alpha、sound、particle |
| `WorldProgressionState` | invasion/boss/event authority、typed score/wave if truly gameplay-used | icon、message、packet wave |
| one registry per Tile table | immutable Tile classification | generic `TileData` God Object、dynamic frame cache |

## 9. Implementation checkpoint

P01 owner code is present in `src/Terraria.Dome.Simulation`: the six immutable Tile registries,
`DungeonSpawnPoint`, invasion progress projection, `WorldBoundaryPolicy`, `WorldRuleQuery`, and
`WorldSurfacePolicy`. `LegacyWorldBorderPolicy` delegates to the typed boundary owner and
`WorldMetadata` exposes the named surface query. Existing `WorldRuleState` remains the storage
owner for rain, mode, difficulty and derived `IsRainingForever` state.

The P01 implementation now covers all 17 declared cards as server-owned code (`100%`) at the
typed owner/query boundary. `invasionProgressIcon` remains intentionally excluded as a
display-only projection; the wave card remains transient and does not become a packet or UI
owner. This exceeds the P01 80% stopping threshold without migrating non-server fields.

The progression expansion also exposes server-only queries for hard mode, Blood Moon, Eclipse,
Slime Rain, invasion progress/max/active state, Meteor scheduling, and Lantern Night through
`WorldProgressionQuery`; these are derived from the existing immutable progression state and do
not introduce client presentation fields.

The remaining server-owned secret-seed flags are now represented as nullable immutable fields on
`WorldMetadata` (`IsDrunkWorld`, `IsEverythingWorld`, `IsDontStarveWorld`, `IsNotTheBeesWorld`,
`IsZenithWorld`, `IsTenthAnniversaryWorld`, `IsVampireWorld`, `IsInfectedWorld`,
`IsTeamBasedSpawnsWorld`, and `IsDualDungeonsWorld`). `WorldSeedRuleQuery` provides fail-closed
queries, and `WorldGenerationRequest` combines metadata flags with its existing generation rule
snapshot. No client presentation or protocol state is introduced.

The serial Release build completed through `Build/Tools/Invoke-SerialDotnet.ps1` with 0 warnings
and 0 errors; the artifact is under `Build/bin/Terraria.Dome.Simulation/Release/net10.0/`.
No test or verifier command was run per the task boundary.

The remaining server-owned progression fields `Main.pumpkinMoon`, `Main.snowMoon`, and
`Main.slimeRainKillCount` are now represented by immutable `WorldProgressionState` members and
explicit `WorldProgressionQuery` accessors. Legacy source anchors are `Main.cs:681` and
`Main.cs:771-773`; the Slime Rain reset/flow references are `Main.cs:7771-7859` and
`WorldGen.cs:6438`. State-copy transitions preserve all three values, while the current
simulation has no NPC-death counter command, so no fabricated increment lifecycle was added.
These are server progression values only; no UI, packet, or display projection was introduced.

`Main.invasionWarn` is also represented as `WorldProgressionState.InvasionWarningTicks`, with
non-negative validation, immutable update support, and the derived
`WorldProgressionQuery.IsInvasionWarningActive` query. The existing
`WorldInvasionWarningSystem` remains the behavior owner for movement/arrival cadence; because
the current simulation has not exposed those inputs at its progression command boundary, no
synthetic warning invocation was added.

The Legacy `slimeWarningTime` and `slimeWarningDelay` pair is now explicitly represented by
`WorldProgressionState.SlimeRainWarningTicks` and
`WorldSlimeRainWarningPolicy.DefaultDelayTicks` (`420`), with
`WorldProgressionQuery.IsSlimeRainWarningActive` for server consumers. Warning message
publication remains a separate projection and is not part of this state owner.

`Main.isThereAWorldSurface` is now explicitly owned by `WorldSurfaceQuery.IsThereAWorldSurface`;
the query preserves the Legacy `worldSurface > 50.0` threshold and fail-closed behavior for
 missing or non-finite metadata. `WorldMetadata.HasWorldSurface` delegates to this owner.

`Main.GameUpdateCount` is explicitly owned by `WorldGameUpdateCountProjection` and queried via
`WorldGameUpdateCountQuery.Value`. The projection is advanced once per simulation tick and is
exposed read-only by `DomeSimulation`; it is not copied into world persistence, protocol state,
or visual timing.

The existing `WorldWeatherState` query owner now accounts explicitly for Legacy `raining`,
`rainTime`, and `maxRaining` through `IsRaining`, `RainTime`, and `MaximumRainStrength`.
Likewise, the progression ledger marks the already immutable Pumpkin Moon, Snow Moon, Slime Rain
time, and Slime Rain activity fields as accepted narrow slices; restart persistence and complete
event side effects remain partial by design.

`Main.oldMaxRaining` is carried as the transient
`WorldEnvironmentTransition.PreviousMaximumRainStrength`, populated from the prior
`WorldRuleState` by `WorldWeatherSystem`. It remains a server transition baseline and is not
persisted or projected into cloud/render state.

Lantern Night and meteor scheduling are now represented by the existing immutable progression
owners `WorldProgressionState.IsLanternNight` and `WorldProgressionState.IsMeteorScheduled`,
with `WorldProgressionQuery.IsLanternNight` and `WorldProgressionQuery.IsMeteorScheduled` as
the read boundary. Their event scheduling and transition systems consume these states; restart
persistence, Lantern Night presentation, and meteor generation side effects remain partial.

An omission audit found no unowned P01 server field at the typed boundary. The previously
unmarked `slimeRainKillCount` now has immutable storage and a query, but remains partial because
the simulation exposes no NPC-death increment command. Wind target/current likewise have
validated `WorldRuleState` storage, `WorldWeatherState` queries, and tick/command transitions;
wind counter persistence, extreme-wind lifecycle, and seeded random provenance remain open.

A second ledger audit found that world geometry and clock rows were implemented but not marked:
`WorldMetadata.Name`, coordinate/section dimensions, `WorldGrid` geometry, and
`WorldClock` day/night/time/moon/pause owners are now reflected in the parent plan. Their
persistence and legacy import boundaries remain partial where the row says so; visual time and
client-only fields remain excluded.
