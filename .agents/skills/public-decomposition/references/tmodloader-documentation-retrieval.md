# tModLoader 文档检索

## 适用范围

此流程只用于从 <https://docs.tmodloader.net/docs/stable/index.html> 获取 Terraria 或 tModLoader
公开类型和成员的已文档化语义。它不能确认目标仓库私有封装、实际调用顺序，或文档未明确
说明的持久化和网络行为。

## 检索流程

1. 先写下查询目标：声明类型、精确成员名，以及要确认的事实（类型、读写语义、生命周期、
   可空性或公开 API）。不要只按字段名猜含义。
2. 打开稳定版首页，记录页眉中的版本和页面标题。首页可见的 `Classes`、`Packages` 和
   `Class Members` 是检索入口；搜索框仅作辅助，空的动态搜索结果不是“该 API 不存在”的证据。
3. 在 `Classes` 中按精确类型名定位。读取页面上该链接的**实际 href**，再打开它；不得猜测 URL
   文件名或用类型名拼接路径。若同名类型不唯一，先用 `Packages`/命名空间或类页的声明信息消歧。
4. 在已确认的类型页中按精确成员名定位。用声明类型、成员区段（数据、属性、方法等）、签名和
   摘要消除重名结果；读取成员链接的**成员锚点**，将类型页 URL 与锚点组合为可复查的 evidence URL。
5. 只从该页明确的签名、摘要和说明推出结论。记录类型页标题、版本、查询词、命中数、完整 URL
   与足以支持结论的原文摘要；没有明确说明的语义保持 `partial` 或 `missing`。

## 无法定位时

| 情况 | 处理 |
| --- | --- |
| 类型未在 `Classes` 找到 | 查 `Packages`/命名空间，再查 `Class Members`；记录已查入口和精确查询词。 |
| 搜索框没有结果 | 改用可见索引，不把空结果当作缺失结论。 |
| 成员有多个同名命中 | 只接受声明类型、成员区段和签名都匹配的锚点；否则记录候选并保留 `partial`。 |
| 页面无法打开或版本不匹配 | 记录不可用或版本差异，按 `ecs-evidence-protocol.md` 的本地源码回退顺序继续。 |
| 关键字段仍无法确认 | 记录 `missing`，停止最终拆分并向调用者说明需补充的类型、版本或源码位置。 |

## 证据记录

每次查询在成员清单或证据日志中保留下列字段：

| 字段 | 填写内容 |
| --- | --- |
| `source` | `tModLoader stable API documentation` |
| `version` | 首页页眉显示的版本，如 `tModLoader v2026.07` |
| `query` | 声明类型和精确成员名 |
| `hits` | 已核对的类型/成员命中数和消歧理由 |
| `evidence` | 带成员锚点的完整 URL、页面标题、签名或摘要 |
| `gaps` | 文档未说明、版本不匹配或候选冲突的部分 |
| `stop_reason` | 已获得充分证据、转本地源码，或关键证据仍缺失 |

示例：查询 `Main.player` 时，先由 `Classes` 页面取得 `Main` 的实际链接，再在 `Main Class
Reference` 页取得 `player` 的成员锚点；证据 URL 必须指向该锚点，而不是只记录首页。
