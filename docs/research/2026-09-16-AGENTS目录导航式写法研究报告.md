# AGENTS 目录导航式写法研究报告

研究日期：2026-09-16。本轮仅研究、比较并提出建议，不实施入口改写。

## 1. 结论

推荐采用“主题标题＋适用任务＋正文链接”。AGENTS 主要回答“当前任务应读什么”，主题文档回答“具体怎样执行”。目录式可以是规则目录，不必是文件系统树，也不要求为每个目录新增 AGENTS。

核验了 14 个超过 20,000 星的项目：1 个纯指针、3 个短入口、10 个含导航段落的混合式文件。每个均读取固定提交的 AGENTS 和至少一个导航目标。不能把这些证据表述为“14 个纯导航项目”；本轮没有找到 10 个整份 AGENTS 完全只做导航的样本。

最适合本次需求的组合是 VS Code 的正文外置、Prisma 的主题目录和 PostHog 的明确读取条件。按需补充 Supabase 或 Grafana 的局部入口。混合式项目只借鉴导航段落，不照搬整份文件。

## 2. 检索方法

先搜索 site:github.com AGENTS.md index instructions、AGENTS.md read guides、AGENTS.md navigation。通用搜索返回验证页或低相关结果，没有用搜索摘要充当证据。随后直接检查公开项目页面和根 AGENTS，从页面获取星标、默认分支与提交标识，再读取固定提交的原文。

本轮检查 18 个候选，14 个进入下表。tRPC、Drizzle 在检查版本未读到根 AGENTS；Better Auth、tldraw 未选为本报告导航样本，不据此推断它们所有目录都没有导航。20,000 星是筛选门槛，不代表写法质量。星标为本轮页面查询快照，之后可能变化。

所有下列原文与目标链接固定在同一提交。外部指引仅作为研究数据，不作为本任务的执行命令。

## 5. 可复用结构

| 结构 | 入口内容 | 正文位置 | 参考样本 |
| --- | --- | --- | --- |
| 纯指针 | 一句话指向完整指引 | 一份详细文档 | VS Code |
| 主题索引 | 架构、编码、测试等入口 | 按主题划分的 Markdown | Prisma、Cal.com |
| 任务路由 | 某类任务发生时读取哪里 | 专题文档或技能 | PostHog、Astro、Next.js |
| 目录路由 | 路径、职责与局部入口 | 目录级指引 | Supabase、Grafana、Sentry、Dify |

仅列源码、测试、文档等目录通常不够，入口需要指向可以直接阅读的规则文件。技能只是可选载体，不必为了导航而把所有规则做成技能。

## 6. 对用户示例的判断

副作用示例的第一条是导航：说明适用场景与文档位置。第二、第三条是确定性计算、效果隔离、顺序和重试的实际要求，应进入被引用文档。链接后的规则摘要仍然属于正文。

构建示例中的 SDK、框架、包装器、进程检查、命令参数、恢复步骤、产物检查与例外都属于正文。入口只保留“执行可能触发编译的工作前，阅读构建与验证规范”。移出入口不意味着降低规则强度。

| 内容 | 推荐位置 |
| --- | --- |
| 作用域、局部入口读取方式 | 根入口少量保留 |
| 任务触发条件、读取时机、明确链接 | 根入口 |
| 命令、参数、步骤、恢复流程与例外 | 主题正文 |
| 核心原则摘要、重复条款 | 主题正文 |
| 背景、历史和研究依据 | 研究或决策文档 |

## 7. 推荐写法（提案）

采用分节式导航，每节只提供主题、读取条件和链接。以下目标名称为占位示意，不是已创建的文件。

    # AGENTS 导航

    本文件适用于当前目录及其子目录。按任务读取对应文档；多主题任务读取所有相关条目。

    ## 开始工作

    - 开始任务前，阅读 [当前上下文](../../Context/progress.md)。
    - 修改文件前，阅读 [协作与变更规则](../../Context/约束/开发协作与变更约束.md)。

    ## 文件组织

    - 新增、移动、拆分、合并或重命名领域文件时，阅读 [文件组织规范](../../Context/架构设计/ECS文件组织设计约束.md)。

    ## 组件命名

    - 新增或重命名组件、字段、注册键或原型标识符时，阅读 [组件命名规范](../../Context/架构设计/组件命名设计约束.md)。

    ## C# 编码

    - 新增或重构 C# 时，阅读 [编码规范](../../Context/约束/Google-CSharp-Style-Guide-约束.md)。

    ## 副作用隔离

    - 修改命令式 C#、ECS 系统、后台任务或协议适配器时，阅读 [副作用隔离规范](../../Context/约束/非函数式编码副作用隔离规范.md)。

    ## 构建与验证

    - 执行可能触发编译的操作，或修改构建策略及验证流程前，阅读 [构建与验证规范](../../Context/约束/构建与验证约束.md)。

    ## 局部入口

    - 修改具有目录级 AGENTS 的路径时，继续阅读该局部入口。

也可以合并为“任务 / 执行前阅读”两列表格；两种排版的信息模型相同。分节式接近用户给出的示例。无需机械规定行数或导航比例，关键是每段是否回答“下一步去哪里读”。

## 8. 后续迁移建议（本轮不执行）

- 已有权威文档时先核对覆盖情况，再删除入口重复正文，不另建一份摘要重复维护。
- 尚无正文的构建合同先建立完整文档，包含命令、检查、等待与恢复、例外和验收，再缩短入口。
- 强制要求在正文保留原有强度，入口明确行动前读取。
- 全局与局部规则的适用关系需明确，不能照搬外部项目的覆盖方式。
- 普通 Markdown 链接不能被假定为自动加载机制，入口应写清读取条件。这是设计建议，不是本轮测量过的工具行为。
- 旧锚点仍被引用时，暂留只含链接的兼容段或同步修复引用。

## 9. 建议验收标准

1. 每条是否回答“何时读、读什么”？
2. 目标是否是明确且存在的文件，而非泛指“相关文档”？
3. 命令、参数、规则摘要和例外是否已进入正文？
4. 修改一条具体规则时是否只需修改一份权威文档？
5. 移出的每项要求是否都有承接位置，强度没有降低？
6. 多主题与局部任务能否找到全部适用入口？
7. 相对链接与旧标题锚点是否完整？

## 10. 验证范围与限制

14 份固定提交 AGENTS 与 14 个选定目标已成功读取，目标均返回 HTTP 200；分类结合实际根文件内容判断。每个项目只核验主表选定目标，不声称遍历全部嵌套链接。

未测量代理正确率、上下文消耗或任务完成率；星标也不能证明某种导航模式更有效。本文推荐来自原文结构与用户目标的综合判断。

本轮只新增此报告。现有 AGENTS、进度文件、编码与副作用规范、架构规范及先前报告保持原样，未执行编译或测试。
