## 1. 结论

Version4 把世界会话状态集中在 `Terraria.Main` 静态字段，把长期进度集中在 `Terraria.NPC` 静态字段，事件类、`WorldFile`、`NetMessage` 和 `MessageBuffer` 又直接读写这些字段。建议建立一个世界会话根，但拆成五个内聚状态组件：

```text
WorldSessionRoot
├─ WorldDescriptorState       身份、尺寸、边界、生成锚点、准备状态
├─ WorldRulesState            难度、特殊种子、邪恶类型、感染与矿脉规则
├─ WorldTimeWeatherState      时钟、昼夜、月相、雨、风、临时天气事件
├─ WorldEventProgressState    Boss/NPC 解锁、入侵、月事件、塔和待办事件
└─ WorldSpawnPressureState    刷怪周期、城镇刷新、事件预算和人口派生值
```

组件只拥有权威数据；`System` 执行状态转换；`Query` 只读计算资格；`Command` 提交跨边界变更；存档、网络和表现是只读投影。`NpcSpawnAiTown`、`TownEconomyAndPersonality` 和 `NpcInteractionAndCommerce` 读取会话快照，但只能通过进度/交易命令反馈世界状态，不能持有或直接修改世界旗标。

### 1.1 与“内容定义目录（ContentCatalog）”的边界

第 4 子系统 `ContentCatalog` 是世界会话的只读规则依赖，不是第六个会话状态组件，也不是
运行时实例仓库。tModLoader 本地镜像的 `ContentSamples` 明确将 `ItemsByType` 等字典中的对象定义为
查询用的参考样本，禁止编辑；它还要求在 `Mod.PostSetupContent` 或之后访问，因为此前条目尚未填充
（`D:\TRbackup\tmodloader-api-docs-stable\class_content_samples.html#details`，`v2026.07`）。Version4
也显示样本表在 `ContentSamples.Initialize` 中清空并以 `SetDefaults` 重建
（`Terraria.ID/ContentSamples.cs:835-905`）。因此不可以把样本对象、定义表或运行时会话快照混为同一
权威源。

```text
ContentCatalog (definitions, IDs, recipes, drop rules; initialized then read-only)
        │  definition lookup / pure rule input
        ▼
WorldSession View ─────────────► Domain Query / System ─────► Command commit
        │                                │
        └─ immutable snapshot ───────────┴────► Persistence / Network / Presentation
```

- `ItemDefinitionCatalog`、`NpcDefinitionCatalog`、`ProjectileDefinitionCatalog`、`RecipeAndDropCatalog`
  和 `*ID` 常量只回答“某类型的默认定义或规则是什么”；它们不保存生命、堆叠、AI、寿命、事件进度、
  入侵计数、世界时钟或天气。
- 内容规则可以读取 `IWorldRulesView`、`IWorldTimeWeatherView` 和 `IWorldProgressView` 作为资格输入，
  但不得直接修改任何会话组件。需要产生世界影响时，只能由领域 System 形成带来源和幂等键的 Command，
  再在提交屏障写入会话。
- `ContentCatalog` 不能成为存档、网络包或世界进度的第二权威源。Persistence/Network Projection
  只投影会话和实例的 typed snapshot；反序列化后再以定义 ID 查目录属于 Adapter 解析，不得以当前样本
  覆盖已保存的运行时状态。
- `Main.player`、`Main.myPlayer` 与 `Main.LocalPlayer` 也不属于目录或会话：本地 API 说明前者是实体
  数组、后两者是客户端本地玩家上下文，服务器的 `myPlayer` 为 255；会话应使用显式玩家实体/账户/
  网络关系输入，不能把客户端本地选择写进世界快照（`class_main.html#a9687e7f510efb7175d2aa8c81cdcbf33`、
  `#a42ee3929161f68a93443261b95643df4`、`#ad16e3f4f93bb8e3ea87505b2d4eae809`）。

### 1.2 与“空间、移动、碰撞与液体”的边界

权威子系统文档把空间/移动/碰撞/液体列为第 6 项，把世界会话与进度列为第 2 项。
两者通过只读环境输入连接，而不是合并成一个组件：

```text
WorldSession (descriptor/rules/time/events 的只读 View)
        │ 边界、地层、昼夜、天气和事件资格
        ▼
MovementIntent -> CollisionQuery -> MovementPhysicsSystem
        │                         └─ 写实体位置/速度/接触结果
        ▼
LiquidFlowSystem -> TileMap/Liquid storage
```

- `WorldDescriptorState.Bounds/SurfaceLayer/RockLayer` 为空间边界、出生点和地层查询提供
  输入；不拥有 Tile、碰撞形状或液体格子。
- `WorldRulesState` 的难度、特殊种子和感染扩散开关可被碰撞资格、刷怪/生态和液体规则
  读取；这些系统只能通过 `IWorldSessionView` 读取。
- `WorldTimeWeatherState` 的昼夜、雨、风和事件时钟是环境输入；风的当前表现值、粒子和
  客户端轨迹仍属于派生/表现投影。
- 液体流动、实体浸液/接触和 Tile 结构变更分别属于 `LiquidFlowSystem`、实体物理系统
  和 `WorldStorage`；`WorldLiquidSnapshot` 不进入 `WorldEventProgressState`。

当前 `src/WorldSession/WorldSessionComponents.cs` 仅是早期字段草案：它已有五类状态，但
把多个公开类型集中在单一文件，尚无对应写入 System、纯 Query、Command、存档 Adapter
或网络 Projection。后续实施应按仓库 ECS 文件约束拆成同名核心类型文件；本报告不直接
修改该源码，也不把草案当作迁移完成证明。

### 1.3 与“世界交互与结构变更”的边界

“世界交互与结构变更”是主要子系统的第 7 项，覆盖 Tile/Wall 放置和破坏、重框架、压力板、电线、逻辑门、机关、传送水晶与 TileEntity 生命周期。它不是第六个会话组件：其权威状态归 `WorldStorage`，世界会话只提供规则、时间、进度与生命周期的只读资格输入。

```text
InteractionIntent / InboundWorldCommand
             │
             ▼
InteractionQualificationQuery
  ├─ IWorldSessionView: Ready、规则、时间、事件进度
  └─ ITileQuery: 边界、Tile/Wall、TileEntity 关系
             │
             ▼
WorldInteractionSystem / WiringInteractionSystem / TileEntityRuntimeSystem
             │
             ▼
TileMutationCommand / WireActuationCommand / TileEntityCommand
             │
             ▼
CommitBarrier -> WorldStorage
             │
             └─ 仅必要时 WorldEventCommand -> ProgressCommitSystem -> WorldSession
```

### 2.1 目标设计文档

- “世界会话与进度”定义为世界级规则、时间、天气、事件、难度、特殊种子、Boss 和入侵进度（`docs/Version4权威游戏模拟系统主要子系统.md:29-38`）。

- 文档要求组件/State 只拥有内聚权威状态，System 执行转换，Query 只读，Adapter/Projection 不得写回权威状态（同文件 `:20-25`）。

### 2.2 与“战斗、状态与归因”的明确交界

主系统文档第 11 项把伤害资格、减伤、治疗、击退、免疫、Buff、死亡和伤害来源归因归于
`CombatAndStatus`。它与本报告的世界会话/进度边界，应按**实例状态转换**和**世界持久进度
提交**划分，而不是按“NPC 死亡前后”机械划分：

```text
Attack / hit intent
  -> DamageResolutionSystem -> Health, Defense, Immunity, Buff instance state
  -> DeathResolutionSystem  -> NpcDeathResolved (实体死亡事实和归因结果)
  -> ProgressQualificationQuery (只读 WorldSession + NPC/事件定义)
  -> ProgressCommitCommand  -> WorldEventProgressState
  -> Persistence / Network projection
```

| 所有权 | 真实代码证据 | 拆分结论 |
| --- | --- | --- |
| 实例生命、防御、免疫、Buff、击退和死亡判定 | `Player.cs:1355-1373,3541-3729`；`NPC.cs:6111-6345,78614-78621`；权威设计报告 `6.12 CombatAndStatus` | 归 `CombatAndStatus` 的实体组件与 `DamageResolutionSystem`/`DeathResolutionSystem`，绝不进入世界会话。 |
| Boss/入侵伤害贡献账本和攻击来源 | `Terraria.GameContent/NPCDamageTracker.cs:143-286` 按实际 NPC、攻击者、伤害累积账本；`Terraria.GameContent/InvasionDamageTracker.cs:32-35` 的 `IncludeDamageFor`、`CheckActive` 为空 | 归 `RandomnessAndAttribution`/战斗归因。会话仅接收已解析结算事实；入侵贡献筛选为 `partial`，不能当作持久进度真值。 |
| Boss 击败、入侵完成、NPC 解锁、塔/Lunar 旗标 | `NPC.cs:65681-65960` 写入 `downed*`、塔旗标；`Main.cs:12542-12684` 处理入侵完成；`WorldFile.cs:1263-1455` 保存 | 归 `WorldEventProgressState`，仅由幂等 `ProgressCommitCommand` 写入；NPC 实例和伤害账本均不是持久旗标所有者。 |
| 世界规则提供的战斗/死亡后规则输入 | `hardMode`、特殊种子和 `downed*` 被掉落、生成和事件资格读取 | 战斗、掉落、生成 Query 只读 `IWorldRulesView`/`IWorldProgressView`；它们不得直接改 `Main`/`NPC` 静态进度，也不得直接存档或发网络包。 |

最小 seam 为 `ProgressQualificationQuery.Evaluate(NpcDeathResolved, IWorldSessionView)` 与
`IWorldProgressCommand.Commit(ProgressCommitCommand)`：前者是纯资格判断，后者在会话提交屏障中
一次性写入世界旗标并产生投影事件。死亡事实必须携带实体身份、NPC 定义标识和归因结果；实体
槽位、网络 ID、玩家账户 ID 与持久化世界 ID 分别建模，不能互换。这样可用命令幂等键处理复合
Boss、多段实体、重复网络包及入侵波次重复结算，而不会把暂态 `NPCDamageTracker` 列表错误保存为
世界历史。

### 与 `ProjectileBehavior` 的边界

主系统文档的第 10 项将投射物归属、轨迹、行为、伤害、穿透、命中免疫和寿命归为
`ProjectileBehavior`。这些是每个投射物实例的状态，不能迁入 `WorldSession`。Version4 的
`Projectile.cs:14807-14809` 读取 `Main.windSpeedCurrent` 来调整特定轨迹，说明其依赖方向
应为 `ProjectileBehavior -> IWorldTimeWeatherView`，而不是让天气组件持有投射物数据。

| 交叉规则 | 合法方向 | 禁止的方向 |
| --- | --- | --- |
| 风、昼夜、难度、世界事件作为弹道/资格输入 | `ProjectileBehavior` 只读 `IWorldRulesView`、`IWorldTimeWeatherView`、`IWorldProgressView` | 会话组件保存 owner、轨迹、AI、伤害、穿透、免疫或 `timeLeft` |
| 命中/死亡导致 Boss 或入侵进度变化 | 投射物 System 发出 `IWorldProgressCommand`，由 `ProgressCommitSystem` 原子提交 | 投射物 System 直接写 `NPC.downed*` 或 `Main.invasion*` |
| 高尔夫、鱼漂、传送门、牵引实体 | 在 `Projectile` 领域分别建立专属状态和 System；仅读取会话 View | 因共享天气/事件输入而塞进 `WorldTimeWeatherState` 或 `WorldEventProgressState` |
| 轨迹历史、粒子、音频、网络脏标记 | Presentation/Network Projection 读取权威状态 | 表现或网络失败反向改变世界/投射物玩法状态 |

权威设计文档把 NPC 模拟与城镇列为第 9 子系统，范围包括刷新、AI、目标、战斗、生命周期、住房、幸福度、对话、服务和任务。本次拆分只迁移其依赖的世界级输入和长期进度；NPC 实例行为与住房关系不回流到 `WorldSession`。

建议的调用方向：

```text
WorldRulesView + WorldTimeView + WorldProgressView + TownHousingQuery
                                ↓
                  NpcSpawnAndTownEligibilityQuery
                                ↓
      NpcAiSystem / TownHousingSystem / NpcInteractionSystem
                                ↓
       Spawn/Despawn/Commerce/ProgressCommit commands
                                ↓
           WorldSessionState + WorldStorage + projections
```

必须阻止三种状态回流：Town AI 不直接写进度组件，而是发 `NpcSavedCommand`；住房不写入 Boss/事件旗标，而由 `TownHousingRegistry` 持有关系；商店/对话/UI 不得以显示价格或文本反向改变世界规则，必须由服务器资格 Query 和交易 Command 决定。

### NPC/城镇证据状态

| 领域 | 证据状态 | 未闭合点与处理 |
| --- | --- | --- |
| Town AI 的昼夜/天气输入 | confirmed | 通过 `WorldTimeView` 读取；实体 AI 迁移需单独 verifier |
| 救援/解锁长期进度 | confirmed（声明和主要写入点） | 分散的 `unlocked*` 写者逐字段补证据；禁止 NPC 实例持有世界旗标 |
| 住房关系 | confirmed（管理器 API） | 与存档、重生、多人同步的原子边界未验证；单独 registry + system |

| 对话/任务/服务 | partial/missing | `NPC.CheckDialogue` 和多个交互实现为空体；先补 focused verifier 再迁移 |

SS14 参考项目只作为组织证据：`SharedGameTicker` 的回合号/时长是只读查询，`GameTicker.RoundFlow` 由私有阶段状态统一发布事件，`GameTicker.GameRule` 用独立实体组件承载临时规则，`StationDataComponent` 保持单一内聚状态。它支持“会话阶段、规则进度、实体行为、投影分离”，不支持复制 Terraria 的领域命名或语义。

## 7. 不拆分项、兼容策略与风险

### 不拆分项

- 不把每个 Boss 旗标做成独立实体；它们共同存档、清理并需要原子快照，保留为 `BossProgressFlags` 子结构。
- 不把 Tile、液体、TileEntity、实体槽位或容器塞入会话组件；它们属于 `WorldStorage`。
- 不把 `WindCurrent`、`cloudAlpha`、`invasionProgressAlpha`、`invasionProgressDisplayLeft`、`CurrentFrameFlags` 当成持久化权威状态。
- 不把账户 ID、网络 ID、实体槽位 ID、持久化 WorldId 和 UniqueId 合并为一个引用。
- 不按文件顺序暗示执行顺序；调度器必须显式表达依赖。

### 兼容迁移

1. 先建立组件与只读 View；旧 `Main.*`/`NPC.*` 仅做单向 facade，禁止新旧字段双写。
2. 将 `WorldFile` 接到 typed snapshot，保留旧二进制字段顺序和版本迁移；加载失败不得半写回。
3. 将 `NetMessage` 改为 snapshot projection，`MessageBuffer` 先做世界 ID、权限、序号、速率和会话状态校验，再提交 Command。
4. 按 `Clock → EventScheduler → SpawnPressure → Ecology → Invasion → Projection` 迁移并逐步删除旧权威字段。
