## 1. 结论

原始实现把四类不同生命周期的东西集中在 `Entity`、`Collision` 和 `Liquid`：

1. 实体的可持续空间状态，例如位置、速度、命中盒与方向；
2. 可重复的几何和 Tile 资格计算；
3. 本 Tick 的接触事实与由接触产生的移动修正；
4. 世界网格中的液体、活跃队列、合并导致的 Tile 事务及网络广播。

因此不能用一个 `MovementPhysics` 组件或一个 `LiquidFlow` 系统承接所有字段。目标模型
应拆为：实体空间状态、移动意图、碰撞策略、接触结果、只读空间查询、位置/速度提交、
世界液体网格、液体工作队列、液体合并事务和网络投影。门、坐骑/矿车和传送各自有跨域
不变量，作为这些核心边界的调用者和命令生产者，而不是追加字段到运动组件。

推荐的权威写入方向为：

```text
输入 / AI
  -> MovementIntentState
  -> MovementCapabilityQuery + SpatialCollisionQuery
  -> MovementResolutionSystem
  -> SpatialMotionCommitSystem
  -> ContactResultBuffer
  -> LiquidContactResolutionSystem / DoorTraversalSystem / MountMovementSystem

TileLiquidState + LiquidWorkQueueState
  -> LiquidFlowSystem
  -> LiquidMergeQualificationQuery + LiquidMergeTypeResolutionQuery
  -> TileLiquidCommitCommand / TileMutationCommand
  -> LiquidReplicationProjection
```

`SpatialCollisionQuery`、`LiquidMergeQualificationQuery` 和
`LiquidMergeTypeResolutionQuery` 只读，不得写实体、Tile、队列或网络。所有位置、速度和
Tile 写入都由明确 System 或提交命令完成；网络、音效、尘埃和客户端预测均为权威状态的
单向投影。

## 4. 建议模块与最小契约

以下名称是 Version4 的建议接口，而非对 SS14 名称的翻译或复刻。每个 State 仅保存一个
共同生命周期、共同写者和共同不变量的概念。

| 模块 | 类别与权威所有权 | 最小输入 -> 输出 | Interface / implementation seam | Depth、leverage、locality |
| --- | --- | --- | --- | --- |
| `SpatialPoseState` | 实体组件；位置、朝向、坐标系。唯一写者为位置提交。 | `SpatialMotionCommit` -> 新位置/朝向 | `ISpatialPoseWriter.Commit(entity, pose)`；可替换为记录 writer。 | 深：空间坐标不泄露 Tile 或网络；高杠杆：所有空间消费者共用。 |
| `KinematicState` | 实体组件；线速度、重力方向、运动锁定、可选加速度。 | 已解析移动 -> 新速度 | `IKinematicWriter.Commit(entity, kinematic)`。 | 深：不含碰撞形状或水状态；位置和速度有同一 Tick 写者，局部性高。 |
| `CollisionShapeState` | 实体组件；宽高、偏移、形状类别。 | Shape request -> 有效 shape | `ICollisionShapeReader.GetBounds(entity)`。 | 防止所有查询读取 Player/NPC/Projectile 派生类。 |
| `MovementIntentState` | 实体组件；控制或 AI 的期望方向、跳跃/下落平台、序号。 | 输入/AI -> intent | `IMovementIntentReader.Read(entity)`；只由命令入口和 AI 写。 | 输入与结果分离，服务器可拒绝、限速或重算。 |
| `CollisionPolicyState` | 实体能力组件或内容定义引用；穿平台、忽略门、斜坡/hoik 及重力策略。 | policy + sweep request -> 查询选项 | `ICollisionPolicyReader.Read(entity)`。 | 将同一 `TileCollision` 的分支参数归为能力，不进入位置状态。 |
| `ContactResultBuffer` | 每 Tick 临时组件/阶段缓冲；Tile、实体、台阶、液体接触及阻塞法线。 | sweep/contact -> `ContactResult` | `IContactResultWriter.ReplaceForTick(entity, result)`；Tick 末清除。 | 只承接事实，不承接伤害、音效或 Tile 改写，减少跨域写入。 |
| `SpatialSnapshot` | 只读世界输入；当前 TileMap revision、形状快照、查询范围。 | store revision -> query input | `ISpatialSnapshotProvider.Capture(revision)`。 | Query 不持有全局可变 `Main`，使纯验证可复现。 |
| `SpatialGeometryQuery` | Query；AABB、线段、可达性、实体间几何。 | shape/line input -> bool/hit | `ISpatialGeometryQuery.Overlaps/HasLineOfSight`。 | 将 `CheckAABBvAABBCollision`、`CanHit` 这类只读计算隔离。 |
| `TileSweepQuery` | Query；Tile、斜坡、平台、门的扫掠判定。 | snapshot + pose + velocity + policy -> `TileSweepResult` | `ITileSweepQuery.Resolve(request)`。 | 必须移除“访问时填充空 Tile”的隐式写入；缺失 Tile 是快照/存储层的显式错误或边界策略。 |
| `StepResolutionQuery` | Query；从 Tile 扫掠结果导出可否上台阶与候选位置/速度。 | sweep result -> `StepResolution` | `IStepResolutionQuery.Resolve(request)`。 | `StepUp` 当前 ref 写入被拆成计算和提交；可单测每种重力、斜坡、平台组合。 |
| `MovementResolutionSystem` | System；唯一产生常规运动提交。 | intent + pose + kinematic + policy + snapshot -> `SpatialMotionCommit`, `ContactResult` | 注入四个 Query 和命令 writer。 | 有明确顺序，不发布网络，不直接改 Tile；最小的权威移动写入面。 |
| `SpatialMotionCommitSystem` | 提交 System；唯一常规写 `SpatialPoseState`/`KinematicState`。 | 有序运动 commits -> 状态更新 | `ISpatialMotionCommitBuffer.Enqueue`。 | 确定性提交点可做回滚、审计和避免两个 System 双写速度。 |
| `LiquidContactResolutionSystem` | System；从已提交位置 + Tile 快照生成实体液体接触。 | pose + shape + TileLiquidState -> `LiquidContactState`、玩法候选 | `ILiquidContactWriter.ReplaceForTick`。 | 世界液体与实体湿润状态分离；岩浆伤害等交给 Combat，不内嵌。 |
| `TileLiquidState` | 世界网格状态，属于 `WorldStorage/TileMapStore`，不是实体组件。 | Tile coordinate -> liquid amount/type/flags | `ITileLiquidStore.Read/ApplyBatch`。 | 持久化和区域复制的唯一权威根；不混入流动队列。 |
| `LiquidWorkQueueState` | 世界调度状态；活跃 cell、延迟、淘汰/缓冲队列。 | Tile liquid changed -> enqueue/dequeue | `ILiquidWorkQueue.Enqueue/TakeBatch`。 | 状态与 Tile 内容分开，允许规定容量、去重和队列溢出恢复。 |
| `LiquidSchedulerState` | 世界会话状态；工作预算、周期、panic/settling 计数。 | session/player count/queue pressure -> work budget | `ILiquidTickBudgetProvider.GetBudget`。 | `maxLiquid`、`cycles`、panic 不应散在静态字段，便于服务器权威存档与诊断。 |
| `LiquidFlowSystem` | System；按固定预算计算流动候选。 | liquid snapshot + work batch -> `TileLiquidCommitCommand` | `ILiquidFlowRules.Resolve(cell, snapshot)`。 | 不广播，不播放效果；同一区域提交须串行或有区域锁。 |
| `LiquidMergeQualificationQuery` | Query；判定相邻液体、数量、容器、可切 Tile、生成模式。 | local 3x? Tile snapshot -> merge/no merge | `ILiquidMergeQualificationQuery.Evaluate`。 | `LiquidCheck` 的读判断与写入分开；无法确认空体分支时返回明确的 `UnknownPolicy`。 |
| `LiquidMergeTypeResolutionQuery` | Query；液体组合到目标液体/Tile 类型。 | liquid types -> `LiquidMergeOutcome` | `ILiquidMergeTypeResolutionQuery.Resolve`。 | 对应 `GetLiquidMergeTypes` 的纯映射，边界验证价值高。 |
| `LiquidMergeTileCommitSystem` | 提交 System；将合并的液体清空、生成/销毁 Tile、重新入队。 | merge command -> Tile batches + requeue | `ITileMutationCommandBuffer.Enqueue`。 | 事务性高：同一批必须含液体、Tile 和帧变化；`CreateLiquidMergeTile` 空体前保持 partial。 |
| `LiquidReplicationDirtySet` | 投影暂存，不是玩法状态。 | 已提交 TileLiquid revision -> dirty coordinates | `ILiquidReplicationSink.Publish(changes)`。 | 对应 `_netChangeSet` 双缓冲；发送失败不得回写液体或队列。 |

| --- | --- | --- |
| `SpatialPoseState` 与 `KinematicState` | 分开，但由同一提交阶段一起写。 | 位置被传送/生成独立写，速度被碰撞/外力独立写；若后续发现任何消费者始终共同读写，才评估合并。 |
| `CollisionShapeState` | 不把宽高并入 `SpatialPoseState`。 | 尺寸是碰撞能力和形态问题，而非位置；传送安全检查、投射物和 Tile Sweep 只需 shape 时应避免读取移动输入。 |
| `ContactResultBuffer` | 保持一个每 Tick 聚合结果，不按法线/液体/台阶过度原子化。 | 这些结果由同一次 sweep 产生并在相同 Tick 过期；拆得更细会使消费者重复扫描 Tile。 |
| 门 | 独立 `DoorTraversal` 和 `TileMutation`，不并入 Physics。 | 门会原子改写 2x3 Tile、帧、机关去重和投影；`DoorOpeningHelper` 处理器为空体，速度窗口的具体策略暂缓。 |
| 坐骑与矿车 | `MountAndMinecart` 保持独立能力域。 | 坐骑有 Buff/能力/投射物关系，矿车有轨道 Tile 与开关事务；两者只生产 movement input 或 Tile command。 |
| 传送 | `TeleportationNetwork` 独立。 | 传送涉及跨实体关系、冷却、落点安全、区段同步，不能作为写 `SpatialPoseState` 的旁路。 |
| 液体合并生成 | 暂不承诺完整实现。 | `CreateLiquidMergeTile`、`UndergroundDesertCheck` 在参考源码为空体；必须补齐源码或行为基线后才把类型/掉落/帧语义升为 confirmed。 |

## 5. 运行顺序、状态所有权与命令方向

### 5.1 每 Tick 的确定性顺序

```text
0  CommandIngress / AI
   只写 MovementIntentState、DoorTraversalIntent、TeleportRequest。

1  Capability preparation
   MountMovementSystem、MinecartTrackQuery、DoorOpeningQualificationQuery、
   TeleportQualificationQuery 只生成或拒绝意图/命令。

2  Spatial resolution
   MovementResolutionSystem 读取同一 Tile/实体空间快照，写入 motion commits 和
   ContactResultBuffer；SpatialMotionCommitSystem 提交位置、速度、朝向。

3  Contact consequences
   LiquidContactResolutionSystem 写 LiquidContactState；DoorTraversalSystem 与
   TeleportResolutionSystem 可产生 Tile/位置提交命令，但不得绕过提交点。

4  World liquid
   LiquidFlowSystem 读取已提交的 Tile 快照和队列批次，产生液体及合并命令；
   LiquidMergeTileCommitSystem 在 TileMutation 提交阶段串行应用。

5  Structure commit and derived topology
   TileMutationCommitSystem 原子提交门、轨道和液体合并；TileFrame/轨道索引更新在其后。

6  Projection
   ReplicationProjectionSystem、音效、尘埃、客户端表现仅消费已提交的状态 revision。
```

必须有下列显式约束，而不是依赖文件枚举顺序：

- `MovementResolutionSystem` 在 `SpatialMotionCommitSystem` 之前；
- `LiquidContactResolutionSystem` 在本 Tick 的空间提交之后、战斗/状态结算之前；
- `LiquidFlowSystem` 读取结构提交后的 Tile 状态，液体合并提交在网络复制之前；
- `DoorTraversalSystem` 和 `TrackSwitchCommand` 不能在 `TileSweepQuery` 正在读取同一
  Tile revision 时直接写 Tile；
- `TeleportResolutionSystem` 先用 `TileSweepQuery` 验证落点，再提交位置、速度和冷却，
  最后发复制事件。

### 5.2 所有权与副作用边界

| 状态/效果 | 唯一权威所有者 | 允许写者 | 禁止写者 |
| --- | --- | --- | --- |
| 实体位置与速度 | `SpatialPoseState` / `KinematicState` | 运动、传送、生成的受控提交 System | Query、网络适配器、表现层、液体流动 System |
| Tile 液体数量/类型 | `TileLiquidState` | 液体和 Tile 事务提交 | 实体接触 System、网络包解析器、客户端表现 |
| 液体活跃队列与 panic | `LiquidWorkQueueState` / `LiquidSchedulerState` | 液体调度与提交 | `TileSweepQuery`、战斗、网络投影 |
| 本 Tick 接触 | `ContactResultBuffer` / `LiquidContactState` | 空间与液体接触解析 | 网络接收、存档、表现层 |
| 门/轨道 Tile | `TileMapStore` | TileMutation 提交 | Physics query、玩家输入、音效 |
| dirty 区域和 DTO | 复制投影边界 | 投影 System | 任何玩法 Query 或业务规则 |

## 6. 参考代码对拆分的实际影响

### 6.1 Version4 证据

- `Entity.cs:10-34` 将 `position`、`velocity`、`direction`、`width`、`height` 与四种
  液体接触标记并置。这是继承基类的便利布局，不是它们具有同一所有权的证据。
- `Collision.cs:74-83` 的 AABB 测试是输入到布尔结果的局部几何计算，可直接成为纯 Query。
  `Collision.cs:829-880` 与 `1001-1085` 读取 Tile 液体判断淹没/水/岩浆接触，适合作为
  `LiquidContactResolutionSystem` 使用的只读输入。
- `Collision.cs:1633-1790` 的 `TileCollision` 读取平台、斜坡、Tile、门等；其中为缺失
  Tile 分配对象的路径说明原实现并非完全无副作用。目标 Query 必须改为读取不可变
  `SpatialSnapshot`，由 `TileMapStore` 事先保证查询域有效，不能在查询中分配 Tile。
- `Collision.cs:2027-2348` 包含实体/Tile 命中处理；`HitTiles` 调用 `WorldGen.KillTile`
  与网络操作，故它应拆为接触/破坏资格 Query 和 `TileHitCommand`，不能放进
  `SpatialGeometryQuery`。
- `Collision.cs:2802` 的 `StepUp(ref position, ref velocity, ...)` 证明台阶会同时影响
  位置和速度；目标中让 Query 返回候选，只有 commit System 写两个权威组件。
- `Liquid.cs:1015-1188` 既按照玩家数调整预算，又处理 panic/settling、`Main.liquid`
  队列、缓冲队列和网络 change set。它必须至少分为 Scheduler、WorkQueue、Flow 和
  Replication 四个职责。
- `Liquid.cs:1190-1233` 的 `AddWater` 可入队、标记 Tile、记录网络变更，且可能
  `WorldGen.KillTile` 与发送消息；目标中“入队资格”和“Tile 摧毁/复制”分别成为
  `LiquidWorkQueue`、`LiquidHazardTileDestructionCommand` 与 projection。
- `Liquid.cs:1238-1320` 同时读取相邻 Tile、清空液体、判定合并并可能摧毁 Tile。
  `Liquid.cs:1324-1394` 的合并类型决策可纯化；真实 Tile 改写必须批提交。
- `PortalHelper.cs:109-214` 用四次 `Collision.TileCollision` 检查落点，再更新速度、调用
  Player/NPC 传送、写冷却并发送网络包。这直接证明传送必须是“资格查询 -> 原子位置/速度/
  冷却提交 -> 复制”的跨域命令。
- `WorldGen.CloseDoor:26186-26292` 与 `OpenDoor:31144+` 会检查空位/锁/Tile 帧后批量改写
  门 Tile，并产生声音或机关效果；所以移动 System 只能产生开门意图。

### 6.2 SS14 组织模式的受限参照

SS14 的 `PuddleComponent` 将可持续流体实体状态放在组件中，`SharedPuddleSystem` 承担
行为；`SlipperyComponent` 和 `SlipperySystem` 将“接触诱发的效果资格/执行”隔开；
`MobCollisionComponent` 保存碰撞缓冲、推力和速度修正，而
`SharedMobCollisionSystem` 显式依赖物理、Transform 和移动修正服务，并声明自己在物理
前更新。该参照只支持下列设计判断：

1. 不将接触持续时间、碰撞推力或网络脏状态塞入通用位置组件；
2. 使用明确 System 持有时间推进、接触迭代和状态改变；
3. 为物理/接触 System 声明更新顺序，而不是由目录或文件名暗示；
4. 网络状态只在指定组件/投影边界同步，不能反向成为服务器物理真相。

SS14 的二维刚体、puddle、slip、fixture 机制与 Terraria Tile 液体和斜坡规则不同，
不构成对 Version4 物理算法、字段名称或领域概念的实现授权。

本次只读核验的精确文件锚点如下，便于复查“组件保存状态、System 执行行为”的组织证据：

| 组织证据 | 参考文件与行 | 仅可支持的判断 |
| --- | --- | --- |
| 流体状态与流体行为分离 | `Content.Shared/Fluids/Components/PuddleComponent.cs:12-29`；`Content.Shared/Fluids/SharedPuddleSystem.cs:31,52,210,250` | 流体实体的配置/引用在组件中，外观与滑移更新由 System 承担。 |
| 接触诱发效果独立 | `Content.Shared/Slippery/SlipperyComponent.cs:15-97`；`Content.Shared/Slippery/SlipperySystem.cs:22,42-50,98` | 滑移参数是组件状态，接触事件订阅与效果尝试由独立 System 执行。 |
| 实体碰撞状态独立 | `Content.Shared/Movement/Components/MobCollisionComponent.cs:11-59`；`Content.Shared/Movement/Systems/SharedMobCollisionSystem.cs:15,23,68,124,168,195` | 推力、缓冲和当前碰撞标记不塞入 Transform；碰撞迭代和速度修正集中在碰撞 System。 |
