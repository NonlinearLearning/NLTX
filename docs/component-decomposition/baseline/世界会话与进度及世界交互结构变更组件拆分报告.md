## 1. 结论

Version4 目前将世界会话的描述、规则、天气、事件和刷怪压力分散在 `Terraria.Main`、`Terraria.NPC`、`Terraria.WorldGen` 及事件类的静态字段中。`WorldFile`、`NetMessage` 和 `MessageBuffer` 直接读写这些字段，世界交互又可经 `Wiring`、`WorldGen` 和 TileEntity 路径改变结构。因此必须先区分两个权威根：

```text
WorldSessionRoot                            WorldStorageRoot
  世界身份、规则、时间、进度                  Tile/Wall/Liquid、区段、TileEntity、容器、槽位
             │                                            │
             └────────────── Query / Command ────────────┘
                                  │
                                  ▼
                         CommitBarrier (主线程)
                                  │
                    Network / Persistence / UI Projection
```

建议的会话组件为：

```text
WorldSessionRoot
├── WorldDescriptorState       世界 ID/GUID、尺寸、边界、层高、出生和地牢锚点、准备阶段
├── WorldRulesState             GameMode、HardMode、特殊种子、世界邪恶、感染和矿脉规则
├── WorldTimeWeatherState       时间、昼夜、月相、雨、风、血月/日食/月事件和天气子状态
├── WorldEventProgressState     Boss、入侵、NPC 解锁、塔/月球、DD2 与待处理事件
└── WorldSpawnPressureState     NPC 刷新周期、城镇刷新优先级、Slime Rain 预算
```

世界交互不应成为第六个会话组件。它应通过 `WorldInteractionSystem`、`WiringInteractionSystem` 和 `TileEntityRuntimeSystem` 操作 `WorldStorageRoot`，仅以只读 Query 获取会话资格，并在确实造成世界事件时发出幂等 `WorldEventCommand`。

## 4. 世界交互与结构变更边界

| 操作 | 输入/纯资格 Query | 唯一写入 | 可选会话反馈 | 不变量 |
| --- | --- | --- | --- | --- |
| Tile/Wall 放置、破坏、重框架 | Bounds、工具/权限、Tile 定义、Session Ready、特殊种子规则 | `TileMutationCommand -> TileMapStore` | `WorldEventCommand`，仅当规则明确要求进度变化 | Query 不写 Tile；重框架后索引与区段脏标记一致 |
| 电线、逻辑门、开关、机关 | `WireQualificationQuery`、时间/规则/事件资格 | `WireActuationCommand -> WireNetworkState/TileMapStore` | 经验证的事件触发 Command | 禁止直接写 Boss、天气、包 7/78 |
| 压力板和座椅/睡眠锚点 | 实体位置、Tile 有效性、Ready | `PressurePlateCommand`、`AnchorBindingCommand` | 无；除非显式事件条件成立 | 关系状态不伪装为位置/Collider |
| 传送水晶、TileEntity 放置/销毁/更新 | 世界规则、坐标安全、实体/持久化 ID 分离 | `TileEntityCommand -> TileEntityStore` | 事件命令需带来源与幂等键 | TileEntity ID、网络 ID、实体槽位和 GUID 不互换 |
| 生态扩散和运行期 Tile 更新 | `WorldRulesView`、Tile/biome Query | `WorldEcologyCommand -> TileMapStore` | 不直接改存档/网络；由投影在提交后读取 | 生成期与运行期通过 Phase gate 分离 |

接口方向：

```text
InteractionIntent / InboundWorldCommand
  -> WorldCommandValidator(sessionId, actor, permission, sequence, rate, bounds)
  -> InteractionQualificationQuery(IWorldSessionView, ITileQuery)
  -> WorldInteractionSystem / WiringInteractionSystem / TileEntityRuntimeSystem
  -> CommandBuffer
  -> CommitBarrier
  -> WorldStorageRoot
  -> optional WorldEventCommand
  -> ProgressCommitSystem
  -> WorldSessionRoot
```

因此，`MessageBuffer` 不应再直接调用 `Wiring.HitSwitch`、`Main.StartInvasion` 或直接设置 `Main.eclipse`；它只能反序列化并验证 `InboundWorldCommand`。`WorldFile` 和 `NetMessage` 也只能从提交后的不可变快照生成投影，失败不可反写权威玩法状态。

## 5. 最小模块契约和调度

## 6. 不拆分项、迁移与风险

- 世界尺寸、边界、层高和生成锚点同属一个加载/生成生命周期，不应拆成多个实体。
- Boss 和 NPC 解锁旗标共同持久化和清理，保留为 `WorldEventProgressState` 的子结构，不逐旗标建实体。
- `WindCurrent`、`cloudAlpha`、`invasionProgressAlpha`、`invasionProgressDisplayLeft`、`CurrentFrameFlags` 是派生/表现数据，不能成为存档或网络真值。
- 不将 TileMap/TileEntity/实体槽位塞回世界会话；不把会话规则塞到交互组件；不依赖文件顺序作为系统顺序。
- 第一阶段建立会话组件、WorldStorage 与只读 facade，旧静态字段只单向转发。第二阶段以 typed snapshot 接 `WorldFile` 和包 7/78。第三阶段迁移 Clock、事件、交互和进度 System。每个边界通过 focused verifier 后，才移除旧写者。

| 风险 | 证据 | 处理 |
| --- | --- | --- |
| `WorldGen.clearWorld` 跨十余类静态状态 | `WorldGen.cs:6389-6667` | 统一 `WorldCleared` 事件，逐字段 reset verifier |
| temp staging 和旧存档版本混用 | `WorldFile.cs:98-180, 2010-2186` | 版本化 Snapshot、原子 load/rollback |
| 包 7/78 和入站事件混合状态投影/命令 | `NetMessage.cs:221-403`; `MessageBuffer.cs:2114-2247` | Projection 与 Command Adapter 分离；验证 world/session/permission/sequence/rate |
| 事件算法为空 | Birthday、Lantern、Sandstorm、DD2 文件 | 标记 partial/missing，补算法和 focused verifier 后才迁移 |
| `ignoreErrors` 吞掉 Tick 异常或替换实体 | `Main.cs:11505-11614` | 明确 fault policy；提交屏障不得吞掉半完成会话/结构状态 |

## 7. 验证计划与实际结果

应建立的 focused verifier：

- `SessionReadyQuery`：加载、生成、Ready、失败、卸载期间实体/结构 Tick 的门控。
- 时钟、雨风、事件：昼夜边界、暂停/快进、随机源可重放、事件启停和清理。
- 进度：入侵 Start→Warn→Wave→Kill→Complete，Size 非负且完成幂等；Boss/塔/月球进度重复提交只生效一次。
- 结构：Tile 放置/破坏/重框架、电线、压力板和 TileEntity 的 Query 无副作用；提交屏障前后可见性、索引与区段脏标记一致。
- 存档：Save→Load 覆盖世界身份、规则、天气、入侵、Boss/NPC 解锁与事件；截断、非法枚举和旧版本缺省字段必须原子失败。
- 网络：包 7/78 snapshot 一致；错误 world ID、权限、序号、频率、距离或未 Ready 的入站命令全部拒绝。
- 故障：事件、结构、存档和网络投影异常均不能提交半成品或反写会话状态。

实际结果：已完成文档/源码/SS14 组织模式的只读检索和本报告；未修改运行时代码，未运行编译或测试。故本报告为可实施的组件化拆分设计，不是迁移完成或回归通过的证明。
