# Version4 非权威 20 分区组件实现审计报告

审计日期：2026-09-15  
审计范围：非权威 P01-P20 的 20 份 design、20 份 execution、20 份输入报告、当前 `src2` 源码及项目文件  
审计目标：比较设计文档、执行报告和代码文件，确认组件源码是否存在、是否被项目包含、是否有验证证据，以及报告中标记的阻塞项。

> 历史快照：本报告记录 2026-09-15 的 P01-P20 审计范围。2026-10-02 起，P16、P17、P19、P20 已退出当前非权威分区范围；本报告中的相关状态只保留为历史观察，不代表现存文档或源码。

## 一、结论

20 个非权威分区都有不同程度的 `src2` 候选源码，但没有一个分区可以仅凭当前证据认定为生产迁移完成。必须区分以下四个层次：

1. `.cs` 文件存在且非空。
2. 对应 `.csproj` 实际包含该文件。
3. 当前源码可以通过 build/verifier，且 verifier 不是复用旧产物。
4. 已接入生产 `src`、网络、持久化和最终调度，并完成行为等价验证。

本次多数分区最多达到第 1 层，部分达到第 2 或第 3 层，没有证据证明 20 个分区整体达到第 4 层。`src2` 是非权威候选实现树，不能等同于生产 `src`。

20 份输入报告的成员总数为 4542，runner ledger 的成员数与输入报告一致。当前 ledger 状态为：

| 状态 | 分区 |
|---|---|
| `completed` | P01-P14、P18-P20 |
| `available` | P15 |
| `running` | P16、P17 |

ledger 的 `completed` 只表示会话生命周期完成，不表示组件已经实现、编译包含或完成生产接入。

## 六、重点技术证据

### P08 loadout swap 失败

`EquipmentLoadoutComponent.SwapWith` 先将 `Armor` 复制到对方，再从已经覆盖的对方复制回自身；Dye 和 Hide 也有同样问题。代码位于：

`src2/PlayerInputGameplay/Equipment/EquipmentLoadoutComponent.cs:31-36`

因此 verifier 的断言“交换后双方保留各自值”失败。

### P12/P13 项目包含边界

P12 设置了 `EnableDefaultCompileItems=false`，只 Include 指定目录；P13 的项目只 Include Chat。源码存在不能证明这些分区的所有源码进入对应项目。

### P10 当前源码树

当前 `src2/EconomyCraftingFishingLoot` 实际有 99 个 `.cs`：

- `Commerce/ShopInventorySlotsComponent.cs`
- `Fishing/AnglerQuestStateComponent.cs`
- 97 个非 Component 源文件

这与 execution 中“只保留两个 Component 文件”的记录不一致，应重新确认这些文件的来源、是否属于当前会话以及项目编译边界。
