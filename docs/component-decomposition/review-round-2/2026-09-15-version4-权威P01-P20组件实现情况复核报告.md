# Version4 权威 P01-P20 组件实现情况复核报告

审计日期：2026-09-15  
审计范围：权威分区 P01-P20 的设计文档、执行报告、逐成员源码映射及当前 `src/**/*.cs`   
审计目标：比较设计与执行文档声明和实际源码，确认组件及其运行时边界是否已经实现。

## 一、总体结论

权威 runner 的 P01-P20 成员数量均与分区清单匹配，但这只能证明分区清单一致，不能证明运行时迁移完成。

当前证据不能证明任何一个权威分区已经完成完整的行为迁移。多数分区已经存在组件数据结构或局部系统源码，但仍属于 `source-only` 或 `partial`，缺少一个或多个关键闭环：

- 运行时注册和生命周期接线；
- 唯一写者及旧状态迁移；
- System、Query、Command、Adapter 或 Projection；
- 网络同步、存档和恢复；
- 调度、并发、重试或完成屏障；
- 与 Player、NPC、Projectile、TileEntity、WorldStorage 等边界的行为等价。

## 二、判定口径

本报告区分以下状态：

| 状态 | 判定含义 |
|---|---|
| `implemented-source` | 对应 `.cs` 文件真实存在且非空；只代表源码落盘，不代表完整行为迁移。 |
| `partial` / `source-only` | 组件数据结构或局部边界存在，但 System、Query、Command、Adapter、Projection、唯一写者、生命周期、网络、持久化或行为等价尚未闭合。 |
| `not-implemented` | 文档或执行报告中的目标仍为 `proposed`、`planned`、`pending`、`deferred`，且对应源码文件或边界不存在。 |

以下情况不能单独作为“完整实现”的证据：

- 文档标注 `implemented` 或“已保存”；
- 对应 `.cs` 文件存在；
- focused verifier 曾经通过；
- 分区成员数量与 ledger 一致。

“未实现”表示源码文件或对应边界没有落盘；“未闭合”表示源码存在，但运行时所有权、行为等价、网络、存档、调度或跨分区接线仍然缺失。

## 四、文档矛盾与路径漂移

复核发现以下问题会影响执行报告的可信度：

1. P04、P08、P13 的文档状态与成员级 `deferred`、`pending` 内容互相矛盾，顶部状态不能代表所有成员已经完成。
2. P16-P20 存在设计路径与实际源码路径漂移，不能只按文档路径判断源码不存在。
3. P17 之前按 `dome/src` 路径判断的 9 项缺失已复核为误报，实际源码平铺在 `src/WorldSession`。
4. P18 顶部状态容易让人误以为完成，但 secret-seed 组件仍只是数据形状，缺少 canonical owner 及运行时接线。
5. P20 C12 虽然被列入组件范围，但执行报告已经显示其只有局部复制逻辑，不能视为完整 world-generation planning 边界。
6. P11 的设计文件名与实际系统文件名存在漂移：文档提议 `PlayerPoseAndAnimationStateSystem.cs`，实际源码为 `PlayerPoseAndAnimationSystem.cs`。

## 五、验证边界

本轮没有新增运行 `dotnet` build/test。表中出现的 build 或 verifier 结果均为设计/执行报告中已有的历史记录，不能当作本轮 fresh verification。

任何后续构建验证都必须遵守仓库的 `BUILD-CONCURRENCY-1` 约束：

- 先检查活动的 `dotnet.exe` 和 `csc.exe` 进程；
- 从仓库根目录通过 `Build/Tools/Invoke-SerialDotnet.ps1` 执行；
- 使用 `-m:1`、`-nr:false`、`-p:UseSharedCompilation=false`、`-p:MSBuildNodeReuse=false`、`-p:BuildInParallel=false`；
- 每次只运行一个 compile-capable 命令；
- 验证 `Build/bin/` 下的预期产物，并记录命令、项目、退出码、警告数、错误数和产物路径。

## 六、审计方法补充

本次按 PUA 检查要求对关键结论进行了反向核验：

- 先搜索并读取原始设计文档、执行报告和源码，而不是直接接受文档状态；
- 对“文档已实现”“源码文件存在”“focused verifier 通过”等假设逐项反转检查；
- 对路径漂移、字段缺失、owner 冲突和历史验证边界进行最小隔离确认；
- 在发现单一路径判断可能误报时，转向全局源码搜索并复核实际命名空间和目录布局；
- 保持审计为只读检查，没有修改源码、设计文档、执行报告、ledger 或 lock。
