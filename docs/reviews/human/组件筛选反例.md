# 组件筛选反例

记录日期：2026-10-13。  
canonical 路径：`docs/reviews/human/组件筛选反例.md`。

本文记录组件保留筛选中的分级反例，作为后续修订分级与保留清单的依据。
原始分级见 [简单游戏组件分级审核](../audits/2026-10-08-simple-game-component-grading.md)
和 [逐组件分级清单](../audits/2026-10-08-simple-game-component-grading.csv)。

## 1. DamageContributionComponent

| 项目 | 内容 |
| --- | --- |
| 原清单编号 | C069 |
| 领域 | Combat |
| 原建议等级 | L2：通用可选玩法 |
| 组件源码 | [DamageContributionComponent.cs](../../../src/NSSLC/Components/Combat/DamageContributionComponent.cs) |
| 组件作用 | 按伤害来源实体累计伤害贡献，供多人贡献统计、击杀分配和战斗账户规则使用。 |
| 筛选结论 | 不适合归入 L2，列为 L2 保留筛选反例。 |
| 替代等级 | 用户尚未指定。 |

### 原分级理由

> 多人贡献、击杀分配和战斗账户属于附加规则，基础伤害运算不依赖贡献统计。

### 反例原因

用户提出：

> 多人的伤害系统不适合在 L2 分级。

具体到此组件，它保存各伤害来源的累计贡献，主要服务多人伤害贡献与分配规则。
用户认为这类多人玩法需求不适合归入 L2 的通用可选玩法范围，因此否定该组件原有的
L2 分类。后续修订 L2 保留清单时，应纳入这条筛选意见。

本条记录确认的是对 L2 分类的否定；替代等级尚未决定，原始分级清单继续作为历史依据。

## 2. EncounterDamageCreditComponent

| 原建议等级 | L2：通用可选玩法 |
| 组件源码 | [EncounterDamageCreditComponent.cs](../../../src/NSSLC/Components/Combat/EncounterDamageCreditComponent.cs) |
| 组件作用 | 保存一次战斗的玩家账户贡献、世界伤害、最后贡献者、统计时间和账本生命周期。 |
| 筛选结论 | 不适合归入 L2，列为 L2 保留筛选反例。 |
| 替代等级 | 用户尚未指定。 |

### 原分级理由

> 多人贡献、击杀分配和战斗账户属于附加规则，基础伤害运算不依赖贡献统计。

### 反例原因

沿用用户对上一组件提出的筛选标准：

## 3. DoorTraversalComponent

| 项目 | 内容 |
| --- | --- |
| 原清单编号 | C099 |
| 领域 | Physics |
| 原建议等级 | L2：通用可选玩法 |
| 组件源码 | [DoorTraversalComponent.cs](../../../src/NSSLC/Components/Physics/DoorTraversalComponent.cs) |
| 组件作用 | 保存自动开关门追踪、穿门方向和时刻，以及按速度开门的有效窗口。 |
| 筛选结论 | 不属于主干游戏组件保留范围，列为 L2 保留筛选反例。 |
| 替代等级 | 用户尚未指定。 |

### 原分级理由

> 自动追踪和按速度开门是额外交互，基本移动碰撞可以不启用。

### 反例原因

用户提出：

> 门属于细化游戏内容，不属于主干游戏组件和游戏系统。

该组件承载自动开关门及按移动速度开门的具体交互状态，属于围绕门展开的细化玩法。
用户本次筛选的是主干游戏组件和游戏系统，因此不将这类门交互状态纳入主干保留范围。
后续修订 L2 保留清单时，应纳入这条筛选意见。

本条记录确认的是对主干保留范围及原 L2 分类的筛选意见；替代等级尚未决定，
原始分级清单继续作为历史依据。

## 4. MotionHistoryComponent

| 项目 | 内容 |
| --- | --- |
| 原清单编号 | C160 |
| 原领域 | Share |
| 完整类型 | `EntityEcs.Components.MotionHistoryComponent` |
| 原建议等级 | L2：通用可选玩法 |
| 历史归位路径 | `src/NSSLC/Components/SpatialSimulation/MotionHistoryComponent.cs` |
| 组件作用 | 保存实体上一轮位置、速度和采样时刻。 |
| 筛选结论 | 原版游戏系统的过度设计，列为 L2 保留筛选反例。 |
| 替代等级 | 用户尚未指定。 |

### 原分级理由

> 上一轮空间采样可支持特定运动算法，最小离散移动不要求独立历史层。

### 反例原因

用户提出：

> 原版游戏系统的过度设计。

用户认为，为当前主干游戏保留独立的运动历史组件属于原版游戏系统的过度设计，
因此将该组件列为保留筛选反例，供后续修订 L2 保留清单时参考。

本条对应原清单 C160 的 `EntityEcs.Components` 类型；原清单另有 C465 的
`Terraria.SpatialSimulation.Components.MotionHistoryComponent`，其原等级为 L4，
不与本条混为同一项。替代等级尚未决定，原始分级清单继续作为历史依据。
