# 禁止 AI 读取：Version4 系统拆分后人工审查与返工

> 本文件仅供人类在当前系统拆分完成后使用。禁止 AI、agent 或自动化工具读取、索引、概括、引用，或将其作为拆分、迁移或验收的输入。
>
> 本文件记录后置人工审查与返工，不是当前 `ecs-system-domain-splitting` 阶段的工作项，也不授权在当前阶段扩展分析器、修改运行时探针或迁移下面列出的代码。

## 启动时点

当前批次的 System 拆分完成后，由人类启动本审查。每个待审查行为切片必须固定当时的源码、配置、测试 world 和输入记录；未经人类确认，不得把任何分析结果标记为调度、生命周期或行为等价的证明。

## 1. 人工代码阅读、调试与迁移确认

人类必须亲自阅读和调试目标代码，并亲自执行后续迁移或返工。每个行为切片至少确认：

- A、B 是否发生于同一 tick，谁先执行，是否存在 commit point、barrier 或延迟可见性；
- 写入属于初始化、普通更新、加载/恢复、网络包处理、异常、重置还是卸载路径；
- 随机数、时钟、文件、网络、线程和锁的实际语义，以及唯一的外部副作用提交者；
- interface、virtual、event、delegate、反射、Timer、Task、线程和序列化入口是否绕过已知调用链；
- 新旧实现的迁移范围、保留的兼容入口、回滚方式和未迁移代码。

每项确认应记录源码锚点、观察或调试方式、结论、剩余未知项，以及由人类完成的代码迁移或返工记录。AI 生成的静态分析、设计建议或文本不能替代此项确认。

## 2. 调度与副作用审查及返工

由人类从 `Main.DoUpdateInWorld`、网络接收、存档加载/保存和其他实际入口复核运行 phase、读写顺序与生命周期。对每个需要返工的 System，明确：

- `must-before`、`must-after`、barrier 和可见性；
- 权威状态写者、派生状态写者和唯一副作用提交者；
- RNG、时钟、文件、网络、线程和锁的归属及隔离方式；
- 需要迁移、拆分、合并、保留或恢复的具体旧代码。

只有人类完成代码迁移并复核实际接入后，才能关闭该行为切片的调度与副作用返工项。

## 3. 运行时 Trace、Replay 与 Shadow 对比审查及返工

在人工确认需要时，建立可重放的输入、tick、随机种子和 world 状态，对比旧路径与新路径。审查至少覆盖状态结果、执行顺序、返回/异常边界、网络包、存档写入和其他外部效果。

Shadow 路径不得同时提交权威状态或外部副作用。差异必须由人类分类为预期变更、数值差异、顺序差异、生命周期问题、真实回归或证据不足，并由人类负责修复或决定保留旧路径。

## 4. 网络与存档映射审查及返工

由人类将 `MessageBuffer`、`NetMessage`、`WorldFile` 与目标状态 owner、协议字段、恢复顺序和兼容要求逐项对应。涉及 Player、NPC、Projectile、Tile、World 或会话状态的迁移，必须明确：

- 入站包如何校验、转换和进入权威状态；
- 出站包如何从权威状态投影，且不会成为第二写者；
- 存档段由哪个 owner 写入、加载后何时恢复、失败时如何处理；
- 协议版本、旧存档和回滚兼容性是否需要保留。

未完成这项人工审查时，不得以组件文件存在、静态分析结果或局部 verifier 通过宣称网络/存档迁移完成。

## 完成记录

每个返工项应由人类记录：目标行为、源码快照、旧/新代码锚点、审查结论、实际迁移内容、验证方式、遗留风险和回滚点。所有适用项完成前，该行为切片只能标记为待人工复核，不得进入旧代码删除阶段。
