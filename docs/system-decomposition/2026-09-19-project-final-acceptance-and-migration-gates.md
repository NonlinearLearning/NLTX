# 项目最终验收与迁移门禁报告

## 结论

项目最终验收是独立于 System 拆分的项目级阶段：

```text
自动门禁
  + 真实接入
  + 行为验证
  + 迁移成功判定
  + 旧实现删除判定
```

它消费 System 拆分阶段产生的候选边界、静态证据包和证据缺口，但不能把静态报告、
编译结果或局部 verifier 直接升级为迁移成功。

System 拆分阶段的静态分析、AI 语义归纳和候选边界规则见
[`System 拆分：静态分析与候选边界设计报告`](2026-09-19-system-decomposition-static-analysis-and-boundary-design.md)。

## 1. 验收范围

项目最终验收需要回答：

1. 新 System 是否已接入真实迁移项目的入口和调度路径？
2. 必需行为测试是否命中新 Owner 和新 API 组合？
3. 新旧实现的完整观察向量是否通过差分？
4. 失败、重复、重试、回滚、网络、存档、恢复、异常和多 world/session 场景是否满足约定？
5. 静态、动态和运行时旧入口残留是否满足删除门禁？
6. 是否可以标记 `migration-success`，以及是否可以删除旧实现？

如果真实接入暴露出新的 Owner、原子不变量或调度边界，必须退回 System 拆分重新分析，
不能用验收结果掩盖边界设计缺陷。

## 2. 验收输入

最终验收消费以下输入：

| 输入 | 作用 |
| --- | --- |
| System 静态报告 | 提供候选边界、概念行为、API 组合、静态缺口和跨分区 seam |
| `SystemStaticEvidenceBundle` | 提供可追溯的成员、入口、关系、Owner 候选和证据身份 |
| 实际迁移代码 | 提供真实接入、注册、主循环、Adapter、Projection 和新 Owner |
| 项目自动门禁结果 | 提供结构、引用、唯一提交者和残留引用检查结果 |
| 真实行为测试结果 | 提供旧实现/新组合的观察向量差分 |
| 运行时追踪 | 提供入口命中、提交点、调度、事件和 effect 的实际证据 |
| 回滚和快照记录 | 提供失败恢复、状态版本和删除后的可恢复性 |

静态证据包是验收输入，不是验收结果。其 `partial`、`unknown` 和动态风险必须进入
最终验收的覆盖范围，不能通过缩小测试输入来消除。

## 3. 自动门禁

自动门禁检查迁移项目是否满足结构和接入前提：

- 目标 System、Component、Query、Command、Adapter 和 Projection 已按契约接入；
- 旧入口、新组合和跨分区契约的映射完整；
- 唯一提交者、禁止双写和角色边界符合项目规则；
- 配置、反射、生成代码、网络、存档和注册入口没有未处理的旧引用；
- 真实迁移项目的必需行为测试和运行时追踪入口已纳入验收范围；
- 回滚点、状态快照、队列/订阅恢复记录和证据链已保存。

自动门禁的通过只说明项目满足验收前置条件，不能单独推出行为等价或
`migration-success`。

## 4. 真实接入

真实接入要求迁移代码进入真实项目边界：

- 真实调用方通过兼容 Adapter 或新 API 进入新组合；
- 新 Owner 已进入真实 System 注册和主循环；
- 事件、命令、队列、网络和持久化路径使用实际项目边界；
- 真实路径中的提交点、barrier 和可见性可以被观察；
- 影子状态或 feature switch 的比较路径不成为第二个对外副作用提交者。

“已设计 Adapter”“旧 facade 仍可调用”或“局部 verifier 可运行”都不是真实接入证明。
最终验收必须记录实际入口、实际新 Owner 和实际组合命中证据。

## 5. 行为验证

旧实现和新 API 组合必须在相同输入、身份、时钟、随机源和外部环境下比较完整观察向量：

```text
Observation = (
  return_or_error,
  authoritative_state_delta,
  emitted_events_and_external_effects,
  order_and_visibility,
  lifecycle_and_scope,
  retry_and_idempotency
)
```

至少覆盖以下场景族：

| 场景族 | 需要确认 |
| --- | --- |
| 正常路径 | 返回值、权威状态 delta、事件/effect 和顺序 |
| 边界输入 | 空值、零值、上限、缺组件、未找到身份和默认值 |
| 拒绝/异常 | 错误类型、状态回滚、是否发出 effect |
| 重复调用 | 累计、幂等、拒绝、重复事件和重复提交 |
| 顺序与可见性 | 前后 API、barrier、队列刷新和同帧可见性 |
| 生命周期 | 创建、激活、更新、结束、死亡、销毁、重建和重置 |
| 跨分区依赖 | 上游失败、下游缺失、事件和共享快照 |
| 外部边界 | 网络、存档、恢复、日志、指标和不可逆 effect |
| 作用域 | 多 world、session、线程和卸载/重载 |

比较时只允许事先记录的表示归一化。最终字段相同不能掩盖事件次数、提交顺序、中间
可见性、错误边界、作用域、重试或不可逆副作用的差异。

## 6. 迁移成功判定

只有以下条件全部满足时，才可以将当前迁移范围标记为 `migration-success`：

1. 真实入口已经命中新 Owner 和新 API 组合；
2. 必需行为测试覆盖约定场景并通过完整 `Observation`；
3. 旧实现和新组合的状态、返回、错误、事件、effect、顺序和生命周期差异均已解释或通过；
4. 失败、重复、重试、回滚、网络、存档、恢复、异常和多 world/session 条件已完成；
5. 未处理的静态、动态、配置、反射、生成代码和运行时入口缺口不再阻断当前范围；
6. 跨分区协调契约和最终 Owner 已由项目级集成审查定案；
7. 自动门禁和行为验证产物与同一源快照、目标快照和迁移版本绑定。

以下事实不能单独标记 `migration-success`：

- System 报告完成；
- 编译通过；
- 静态 API 映射完整；
- 局部 verifier 通过；
- 旧 facade 仍可调用；
- 新 Component 或新 System 文件已经存在；
- 影子路径能够产生看似相同的最终字段。

## 7. 旧实现删除门禁

旧实现删除是最终验收的独立门禁，至少满足：

- 静态、配置、反射、生成代码和运行时入口中的旧引用已处理；
- 旧入口到新概念行为和规范组合的映射已闭合；
- 新旧结果、状态 delta、事件/effect、顺序、错误、生命周期和重试语义已通过；
- 网络、存档、恢复、异常、回滚和不可逆效果边界已确认；
- 队列、订阅、缓存、快照和状态版本的恢复策略已验证；
- 删除后的真实项目仍有可追溯的提交、快照和回滚点；
- 性能、批处理和结构变更成本没有未经解释的回归。

任何一项缺失时，旧实现保持但不得继续新增业务规则，并将状态标记为
`deletion-blocked`。

## 8. 验收证据与状态

最终验收记录至少绑定：

- 源码和目标代码 revision/hash；
- 静态证据包和分析器版本；
- 实际迁移项目、配置、平台和运行环境；
- 真实入口、测试入口和新 Owner 命中记录；
- 行为测试输入、观察向量和差分产物；
- 自动门禁命令、退出码和产物；
- 运行时 trace、网络/存档记录和回滚记录；
- 未通过项、证据缺口、批准的行为变化和删除决策。

建议使用以下项目级状态：

```text
acceptance-not-started
acceptance-partial
acceptance-blocked
behavior-verified
migration-success
deletion-blocked
deletion-approved
```

这些状态只在项目级验收产物完整且可追溯时使用。System 静态报告中的
`static-confirmed`、`proposed` 或 `unknown` 不能自动升级为这些状态。

## 9. 失败与退回规则

以下情况应退回 System 拆分或集成审查：

- 真实调用路径发现未记录的旧入口或动态入口；
- 新接入暴露出多个权威写者或同一不变量的双写；
- 运行时顺序与静态候选的 phase/barrier 不一致；
- Query、Projection 或 Adapter 实际包含领域规则或隐式写入；
- 跨分区 ID、快照、事件、网络或持久化契约缺少最终协调 Owner；
- 行为差分发现未经批准的状态、错误、事件、顺序或生命周期变化。

退回时保留已生成的静态证据和失败产物，更新缺口与重新分析范围，不通过删除证据、
缩小输入或修改报告状态来制造通过结果。

## 10. 阶段交接矩阵

| 事项 | System 拆分阶段 | 项目最终验收阶段 |
| --- | --- | --- |
| 成员和入口库存 | 发现、归类、记录风险 | 复核真实接入范围 |
| 调用/读写/生命周期关系 | 生成静态证据和缺口 | 结合 trace 和行为确认 |
| 概念行为和 API 组合 | 提出候选契约 | 验证完整观察向量 |
| Owner 和 CommitPoint | 提出候选并标记冲突 | 通过真实路径确认唯一提交者 |
| phase/barrier/visibility | 记录静态候选 | 通过真实调度和行为确认 |
| Query/Projection/Adapter | 静态角色审查 | 通过接入和行为确认没有隐式规则或双写 |
| 跨分区 Owner | 标记 `integration-review` | 项目级集成审查定案 |
| 自动门禁 | 不执行项目门禁 | 执行并记录结果 |
| 真实接入 | 只定义入口要求 | 完成并记录命中 |
| 行为验证 | 只定义观察向量和计划 | 执行并比较 |
| `migration-success` | 禁止声明 | 满足完整条件后声明 |
| 删除旧实现 | 记录删除条件 | 执行删除门禁和决策 |

## 11. 最终规则

System 拆分报告提供：

```text
候选边界
  + 静态证据
  + AI 语义归纳
  + API 组合候选
  + 证据缺口
```

项目最终验收提供：

```text
自动门禁结果
  + 真实入口命中
  + 行为观察向量通过
  + 回滚/异常/网络/存档条件通过
  + migration-success
  + 旧实现删除决策
```

前者是 System 设计交付，后者是项目迁移验收。两者不能互相替代。
