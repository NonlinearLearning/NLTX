## 分批范围

### WP0：协议普查与支持矩阵

逐个盘点当前客户端版本的所有消息 ID 和模块消息：方向、真实触发路径、连接阶段、字段/变体、
codec 与 wire fixture、现有 handler/owner、权威状态、副作用、出站同步、限流/权限规则、
测试证据和明确不支持原因。区分正常游戏路径与保留、废弃、开发调试或版本专用报文；冻结
本 CR 的完整覆盖清单、依赖图与更准确的工期。

### WP1：连接、准入与玩家入服生命周期

握手、密码、玩家信息和槽位、角色/装备/背包初始化、属性与 buff、世界加入/出生阶段、重连、
拒绝、踢出和断开清理。先修复标准客户端收到槽位后被拒绝的完整往返。

### WP2：玩家状态、移动与多人互动

控制帧、位置/速度与选择状态、生命/魔力及相关玩家同步、传送/观察、队伍与 PvP 等常规
玩家交互。逐项明确客户端意图与服务端权威状态的边界，避免把客户端字段直接当作可信状态。

### WP3：世界探索与地块操作

世界元数据和区段流、挖掘/放置、墙体、液体、涂装/涂层、门/开关、电线/机关及相关区域更新。
每种操作都定义验证、owner、状态提交、缓存失效、广播和失败响应，并确认世界保存策略；不把
仅解码或回显视为功能完成。

### WP4：物品、背包、容器与经济

物品生成/同步/拾取/丢弃/使用、装备和 loadout、容器及箱子、标牌、制作、商店、NPC 对话和
其他正常物品交互。逐项复用或补齐领域 owner 与持久化路径。

### WP5：战斗、弹幕与 NPC 交互

弹幕同步和生命周期、命中/伤害、玩家死亡/复活、战斗 buff、NPC 状态和常规互动、多人伤害
规则。沿用此前确认的边界：NPC 与弹幕 AI 行为系统暂不实现；协议解码、校验、同步或现有
owner 接入不等于交付 AI 决策及行为模拟。依赖 AI 才能产生的完整游戏结果不列为本 CR 的
完成声明。

### WP6：世界系统与扩展玩法消息

时间/天气/事件、钓鱼与任务、传送门、宠物/坐骑、社交与表情/声音、成就/图鉴、NetModule
等正常玩法消息。WP0 确认当前版本真实正常路径后再锁定此批完整清单，避免按 codec 文件名
推断协议覆盖。

### WP7：多客户端 headless 端到端矩阵

为每个已纳入的正常消息路径提供真实客户端编码/解析验证、网关阶段与权限验证、权威状态和
出站同步断言。覆盖至少双客户端协作场景、重连/断线、无效字段和资源释放；所有测试进程均不
创建 UI/Graphics。最终再用标准 UI 客户端做兼容性冒烟，确认可进入世界并进行各批声明支持的
玩法，不用 UI 测试替代 headless 自动化矩阵。

## 验收标准

1. WP0 的矩阵列明当前版本每个协议 ID/模块的正常使用路径、方向、owner、验证/副作用和测试；
   未实现及非正常路径均有明确结论，不存在把 codec 覆盖误报为服务器支持的情况。
2. 每个正常玩法消息家族至少有一个由真实 Terraria 客户端发送器/解析器驱动的 headless
   成功用例；需要权威状态变更的用例断言提交结果与客户端收到的服务端同步。
3. 无 owner、阶段不符、伪造身份或越界输入按策略拒绝；正常已支持消息不会被静默吞掉，未知或
   非正常消息维持显式拒绝策略。
4. 覆盖的 headless 测试不启动 UI、游戏实例或图形设备；双客户端流程能完成并释放 session、
   槽位和网络预算。
5. 最终报告严格区分“协议接收/同步覆盖”和“模拟/持久化语义覆盖”；NPC/弹幕 AI 仍标记为
   暂不实现，除非用户另行批准扩展范围。

## 影响评估

- **代码范围**：`NSSLC.Infrastructure.Network`、Pocket codecs/生成物消费、网关注册与 owner；
  `NSSLC.Tools.NetworkServer`；真实客户端 `D:/TRbackup/客户端` 的 headless 测试入口、场景
  与验证脚本；对应协议/测试文档。
- **持久化与数据模型**：待 WP0 盘点确认。正常物品、地块、容器等玩法若无现有权威 owner，
  可能需要 WorldFile/角色持久化适配；当前内存 tile 覆盖不能作为最终行为。
- **旧功能影响**：阶段机、消息预算、默认拒绝、玩家槽位生命周期及目前通过的世界同步/
  移动/tile 测试都需持续回归。协议版本变化须重新核对矩阵与 wire fixtures。
- **风险**：协议定义齐全但 owner 或业务规则缺失；多包阶段顺序与客户端版本差异；同一客户端
  消息会触发跨领域副作用；在 AI 明确不实现的情况下，不得宣称 Terraria 全部游戏模拟等价。
- **工期估算**：目前不具备可靠总工期。建议先为 WP0 预留 3–5 个工作日；随后按矩阵中缺失
  的 owner、存档路径和真实报文复杂度逐批重估。全范围是多周至数月级工作，不能按现有探针的
  1–2 天规模估算。
- **验收输入**：当前 Terraria 客户端源码版本、Pocket 协议清单、既有探针证据，以及标准 UI
  客户端入服兼容冒烟。
