## 2. 理由

研究给出的是选型结论，形如「统一错误模型、按层选编码」。结论不是约束：它没有说清哪个机制用在
哪一层、码由谁分配、跨层转换允许几个方向、违反时评审按哪一条退回。于是同一类失败在仓库里
同时存在多种表达。`WorldInteractionResultComponent` 用状态枚举管成败、再用 `string Failure` 管
原因，就是错误模型被劈成两半的现成样本；码与状态枚举又各自为政，既无 facility 也无区间划分，
扩表时无处可依。

约束正文把结论变成可判定条文：每条要么是**必须**／**禁止**（违反即退回），要么是**应当**／
**建议**（偏离须写明理由与撤销条件），并给出一份评审可逐条勾选的验收清单。
