# Pyramid Wall-Framing Request Boundary Design

**Status:** approved for the resumed N6 batch

**Scope:** source-backed request and coordinate expansion only

## Evidence and boundary

`WorldGen.Pyramid` writes wall type `34` for each qualifying center and then calls
`SquareWallFrame(m, n)` at `WorldGen.cs:28425`. The legacy `SquareWallFrame` implementation at
`WorldGen.cs:81820-81834` invokes `Framing.WallFrame` nine times in x-major order:

```text
(x-1,y-1), (x-1,y), (x-1,y+1),
(x,y-1),   (x,y),   (x,y+1),
(x+1,y-1), (x+1,y), (x+1,y+1)
```

The existing generic `SquareWallFrameRequestQuery` uses y-major iteration and has consumers
whose ordering contract is not yet revalidated. The legacy `Framing.WallFrame` implementation also
depends on truncating-wall definitions, large-wall lookup tables, wall-frame lookup tables, and
randomized frame-number selection when `resetFrame` is true. Those semantics are outside this
batch.

This batch therefore owns only the immutable request boundary between Pyramid wall centers and
the nine legacy wall-frame call coordinates. It does not calculate frame values, mutate wall frame
fields, consume random samples, or publish frame commands.

## Recommended design

Add a Pyramid-specific request record and query under
`src/Terraria.Dome.Simulation/WorldGeneration/`:

- `LegacyPyramidWallFrameRequest` records the center, target coordinate, `ResetFrame` flag, source
  name, and source line.
- `LegacyPyramidWallFrameRequestQuery.TryCreateRequests` accepts an immutable snapshot and an
  ordered `IReadOnlyList<WallFrameCoordinate>` of wall centers. It validates every center and all
  nine targets before creating output, preserving duplicates and source order.
- Requests use `ResetFrame = true`, source `worldgen.Pyramid.wall-frame`, and source line `28425`.
- The query does not inspect tile contents, random state, or pending mutations. This allows it to
  describe the calls generated by the footprint command projection without pretending that frame
  calculation has already run.
- Invalid centers, invalid target envelopes, or capacity overflow return `false`, an empty output,
  and a failure reason. No partial request list is returned.

The generic square-wall query is not changed. Integration into the full WorldGeneration pipeline is
also deferred until actual wall-frame semantics and command publication have source-backed owners.

## Invariants

1. For `N` centers, output contains exactly `N * 9` requests.
2. Requests for each center are emitted in the legacy x-major order above.
3. Duplicate target coordinates from neighboring centers remain present; list order is the
   invocation order and is not replaced by a set.
4. Source, source line, and `ResetFrame` metadata are identical for every request.
5. Snapshot contents and metadata are unchanged; the query performs no tile mutation.
6. The query consumes no RNG and does not modify `WorldGenerationStateComponent`.
7. Failure is atomic and fail-closed.

## Explicitly deferred

- `Framing.WallFrame` neighbor classification and truncating-wall behavior.
- `Main.wallLargeFrames`, `wallFrameLookup`, and center-frame lookup semantics.
- `wallFrameNumber` state and `resetFrame` random consumption, including the wall-21 branch.
- `TileFrameCommand` generation and frame-field mutation.
- Pyramid tunnel direction, tunnel clearing, chest/pile/plant/pot side effects, publication order,
  global RNG/checkpoint parity, WLD differential parity, legacy deletion, and the 44 deferred
  `ServerRelevant` ledger rows.
