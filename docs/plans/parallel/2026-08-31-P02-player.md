# P02 Player Declaration Decomposition Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将 Player 的组合字段拆成逐声明核对项，并分别定义移动、专用能力、库存、装备、
Buff、环境和死亡/掉落的 server owner。

**Architecture:** Player 只保留业务身份、权威生命周期和经过授权的可变状态。旧数组、银行、
Void Vault、装备和 Buff 不合并为一个 Player God Object；runtime layout、business
persistence layout 和 legacy compatibility shape 分开记录。

**Tech Stack:** Documentation-only Markdown; no C# changes, no new functions, no tests/builds.

## 4. Three-layout conversion matrix

| Domain | Legacy/source shape | Runtime shape | Persistence shape | Required checks |
| --- | --- | --- | --- | --- |
| Normal item slots | `inventory` physical `Item[59]`；逻辑分区另有 50 item slots | `InventoryComponent` 40 slots | `PlayerPersistentState` 990 slots | index mapping、empty slot、selected slot、overflow、duplicate policy |
| Coin slots | logical legacy slots 50-53 | explicit runtime economy slots or typed items | value-only coin state | coin conversion and loss/restore order |
| Ammo slots | logical legacy slots 54-57 | explicit ammo/equipment domain | value-only ammo state | ammo consumption and fallback order |
| Selected slot | `selectedItem`/`HeldItem` derived access | `SelectedItemComponent` | profile value only if required | invalid slot, empty held item and reset |
| Functional equipment | `armor[20]` | `EquipmentLoadoutComponent` | value-only loadout | functional vs vanity and stat order |
| Dyes/misc | `dye[10]`, `miscEquips[5]`, `miscDyes[5]` | separate equipment/appearance state | only business values | no visual state leakage |
| Bank | `bank`-`bank4` readonly `Chest` | bank store/domain | value-only bank slots | bank identity, capacity and recovery collision |
| Void Vault | `voidVaultInfo` plus Void storage behavior | `PlayerVoidVaultState` | versioned value-only state | disabled/empty/overflow and feature flags |
| Trash | separate `trashItem` | trash slot component | explicit profile decision | destructive transfer and reload behavior |
| Buff | `maxBuffs=44`, `buffType[44]`, `buffTime[44]`, `buffImmune[BuffID.Count]` | bounded BuffCollection | normally derived/transient | ordering, immunity, expiry and reset |
| Death/drop | `dead`, `deadTime`, `respawnTimer`, drop methods | lifecycle + death/drop intent | tombstone/profile policy | exactly-once drop, reconnect and rollback |

禁止添加一个“legacy 58-slot alias”来隐藏 `59/40/990` 的差异。源数组的物理长度、旧逻辑
分区和运行时/persistence 布局必须在 field card 中保持三套独立事实。

## 5. Component and command boundaries

| Owner | Allowed state | Command/system boundary |
| --- | --- | --- |
| `PlayerLifecycleComponent` | active/dead/deadTime/respawnTimer、spawn phase | death/respawn command；一次性 cleanup |
| `PlayerSpawnStateComponent` | `SpawnX/SpawnY`、validated spawn candidate | spawn validation/clear-area command |
| `PlayerMovementStateComponent` | fall origins、ground/liquid contact and movement transitions | movement system；不保存 raw device state |
| `PlayerInventoryComponent` | runtime slots、selected slot、item handle、stack/revision | inventory transfer/use/drop command |
| `PlayerPersistentInventoryState` | versioned value-only normal/bank/Void/trash data | persistence import/export；不复制 wire layout |
| `EquipmentLoadoutComponent` | functional armor/misc capability slots | equipment calculation system |
| `BuffCollectionComponent` | bounded type/time entries and revision | buff apply/expire/immune query |
| `PlayerEnvironmentContactComponent` | breath/lava/water/honey contact | environment damage/resource system |
| `PlayerMountStateComponent` | typed mount capability and mounted state | mount attach/detach/movement command |
| `PlayerGrappleStateComponent` | bounded hook handles and attach state | grapple attach/release command |
| `PlayerLuckStateComponent` | capped luck and effect transition | loot/spawn query; no static global cache |
| `PlayerDefenseStateComponent` | Paladin/shield/parry state | validated defense/use intent |
| `PlayerDeathDropStateComponent` | death cause, exactly-once drop marker, pending world item intent | death/drop commit |

`dye`、`wingFrame`、item rotation、audio handles、animation-only counters和外观缓存如无真实
server consumer 必须标为 `excluded`，不能因为字段位于 Player 类就进入 Simulation。
