# 项目代码规范拆分设计：副作用隔离主题文档

状态：已获用户确认，待按计划实施  
日期：2026-09-02  
范围：`Context/约束/非函数式编码副作用隔离规范.md` 与 `约束/项目代码规范/`

## 1. 目标

将现有“非函数式编码副作用隔离规范”从单篇主题混合文档改造成项目级代码规范入口，
由入口按任务和风险引导 AI 加载多个主题 Markdown。规范不要求改用纯函数式语言，
而是在 C#、面向对象、ECS、后台任务和协议适配器中明确纯计算边界、状态 owner、
command 生命周期和外部副作用契约。

## 2. 目录设计

```text
Context/约束/
├─ 非函数式编码副作用隔离规范.md
└─ 项目代码规范/
   ├─ 00-规范加载协议.md
   ├─ 01-作用域与副作用分类.md
   ├─ 02-纯计算与功能核心.md
   ├─ 03-端口适配器与依赖注入.md
   ├─ 04-状态所有权与不可变快照.md
   ├─ 05-ECS读写集与系统阶段.md
   ├─ 06-Command队列与确定性提交.md
   ├─ 07-持久化消息一致性与Outbox.md
   ├─ 08-异步取消异常与重试.md

```

入口文件保留目标、状态和最小不可违反规则，只负责索引、AI 加载协议、任务映射、
风险分级和冲突优先级；主题文件负责详细规则、示例和执行检查。

## 3. AI 加载协议

1. 每次项目代码任务开始前先加载入口。
2. 按任务触及的目录、类型和副作用选择主题文件。
3. 开始修改前报告已加载主题、适用强制规则、预计副作用和 owner/顺序/失败策略。
4. 涉及两个以上边界时加载所有相关主题。
5. 权威模拟、网络协议、持久化、回放、跨线程和跨模块重构必须全量加载。
6. 无法分类的副作用按最高风险处理，先补充分类和 owner，再实现。

## 4. 作用域模型

- `Domain/Policy/Query`：无外部副作用，只做显式输入到输出的计算。
- `Application/System`：负责编排、读取快照、调用端口和提交 command。
- `Adapters/Infrastructure`：允许访问 SDK、数据库、网络和操作系统，但不承载业务规则。

状态变更采用混合模型：跨模块、跨线程、跨事务、跨 tick、跨网络或需要重试/审计的变更
必须使用 typed command；同一聚合或同一 ECS System 内、同一调用栈中且无需独立排序和重试
的局部状态可以由唯一 owner 通过受控 API 更新。

## 5. 已确认的关键决策

- 时钟、随机数、ID 由 Application/System 通过端口取得，Domain 只接收值；
- 可靠业务消息默认采用 Outbox；进程内 ECS command 按 tick/phase 调度；
- command 默认排序键为 `(tick, phase, systemOrder, producerSequence)`；
- 权威状态、可合并快照、呈现/诊断 command 采用不同的溢出和重复策略；
- command 消费按 command 隔离、按一致性组控制；
- 同一实体、同一一致性组默认 `Validate/Plan → Apply` 两阶段提交；
- 权威模拟与普通业务采用不同确定性级别；
- 快照必须有复制、所有权和深度不可变性契约；
- Domain 不直接依赖日志、指标、Tracing 或审计设施；
- 外部 I/O 端口异步且可取消，Domain 默认同步；
- 方法命名只是可读性约定，真正门禁依靠依赖边界、端口能力拆分、Analyzer 和架构测试；
- 实施分 Level 0 至 Level 4；
- 例外必须有编号、责任人、风险、补偿控制、测试和到期日。

## 6. 统一主题结构

每个主题文件包含：目标、适用/不适用范围、术语、三档作用域关系、强制规则、推荐规则、
禁止模式与反例、C# 示例、ECS 示例（适用时）、数据流和生命周期、失败/重试/取消、
测试、静态检查、评审清单、迁移、例外和交叉引用。

## 7. 优先级与冲突处理

安全与数据完整性 > 架构边界与权威状态 > ECS 确定性与调度 > 可靠消息/持久化/事务 >
异步/取消/重试/资源生命周期 > 测试/静态检查/迁移 > 命名与示例风格。

若两个“必须”冲突，AI 必须停止实现，列出冲突和影响范围，提出最小解决方案并等待架构决策。
未分类副作用默认按可靠业务副作用处理。

## 8. 验收标准

- 入口和 10 个主题文件存在且链接可解析；
- 入口不重复主题正文，能指导 AI 选择和加载文档；
- 每个主题都包含统一结构、强制规则、反例、示例、测试、迁移和交叉引用；
- 已确认决策可定位到具体主题；
- Markdown 标题、表格、代码围栏和相对链接通过基础检查；
- 仅修改文档，不改源代码，不运行无关构建；
- 规范保持“草案/待评审”状态。
