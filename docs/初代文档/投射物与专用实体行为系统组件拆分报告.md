# 投射物与专用实体行为系统组件拆分报告

## 1. 结论与范围

本报告落实《[Version4 权威游戏模拟系统主要子系统](Version4权威游戏模拟系统主要子系统.md)》第 10 项：把投射物归属、轨迹、行为、伤害、穿透、命中免疫和寿命，与高尔夫、鱼漂、传送门、系留实体等专用规则拆开。

结论是：不能把 `Terraria.Projectile` 直接搬成一个 `ProjectileComponent`。该类同时保存定义选择、实例行为、运动、伤害、免疫、生命周期、网络复制和表现轨迹；这些成员的读写者、更新频率和持久化语义明显不同。建议以 `Projectile` 领域为根，按下表的内聚状态模块和显式 System 拆分；专用玩法只在满足条件的实体上附加能力组件。

本报告是设计与源码盘点，不表示该 ECS 实现已经存在。参考代码目录只读：

## 2. 证据记录与缺口

### 2.1 已确认的运行时入口

| 事实 | Version4 证据 | 结论 |

### 3.1 明确不合并的状态

- `ProjectileDefinitionRef` 不与 `ProjectileBehaviorState` 合并：`type/aiStyle` 是定义选择；`ai/localAI` 每 tick 演进。把它们混在一起会让运行时规则改写内容定义。
- `ProjectileDamageState` 不与 `ProjectilePenetrationState` 或目标的生命合并：攻击输出、命中额度和受击生命各有不同写者。
- `ProjectileHitImmunityState` 不与穿透合并：免疫回答“此目标现在能否再次受击”，穿透回答“本实体还能消耗多少次命中”。
- `ProjectileLifetimeState` 不与行为槽位合并：`timeLeft` 的倒计时/结束原因需要统一清理；行为槽位由大量独立 AI 使用。
- `ProjectileOwnerState` 不与动态目标关系合并：所有者是归因/权限来源，目标可随 tick 改变。
- 传送门链接、系留锚点与鱼漂都不进入通用投射物组件。它们只在实体确实拥有该能力时存在，且生命周期与基础投射物不同。

## 4. 推荐模块与最小契约

建议目录先按能力组织。投射物当前规模足以形成稳定的 `Projectile/` 子域；高尔夫、钓鱼、传送和系留有独立规则与验证边界，分别成为相邻领域，而不是建立全局 `Components/`、`Systems/` 收容目录。

```text
src/Shared/
  Entity/
    EntityLocationComponent.cs
  Movement/
    VelocityComponent.cs
  Projectile/
    ProjectileDefinitionRef.cs
    ProjectileBehaviorState.cs
    ProjectileStepSchedule.cs
    ProjectileTrajectoryState.cs
    ProjectileOwnerState.cs
    ProjectileDamageState.cs
    ProjectilePenetrationState.cs
    ProjectileHitImmunityState.cs
    ProjectileLifetimeState.cs
    ProjectileBehaviorSystem.cs
    ProjectileHitEligibilityQuery.cs
    ProjectileHitResolutionSystem.cs
    ProjectileLifetimeSystem.cs
  Golf/
    GolfBallState.cs
    GolfRoundState.cs
    GolfBallSimulationSystem.cs
  Fishing/
    FishingBobberState.cs
    FishingAttemptSnapshot.cs
    FishingOutcomeQuery.cs
    FishingResolutionSystem.cs
  Teleportation/
    PortalEndpointState.cs
    PortalLinkState.cs
    PortalTraversalQuery.cs
    PortalTraversalSystem.cs
  Leash/
    LeashAnchorState.cs
    LeashedEntityState.cs
    LeashBehaviorRef.cs
    LeashConstraintSystem.cs
```

其中 `EntityLocationComponent` 与 `VelocityComponent` 应归属通用位置/移动能力，不复制到 `Projectile/`。所有新增公开类型各自一个同名 PascalCase 文件；上述目录仅是目标布局建议，未创建任何源码目录或文件。

| 模块 | 最小接口/输入 | 输出与唯一写权 | Seam、深度与局部性 |
| --- | --- | --- | --- |
| `ProjectileDefinitionRef` | 不可变 `ProjectileDefinitionId` | 无运行时写入；目录返回定义 | 将内容选择与实例状态隔开；测试可替换定义目录。 |
| `ProjectileBehaviorState` | 有名行为阶段/具名槽位适配，不暴露裸 `float[3]` 给无关系统 | 仅 `ProjectileBehaviorSystem` 写阶段 | 每个行为处理器通过稳定 `IProjectileBehavior` seam 接收状态与只读世界。 |
| `ProjectileStepSchedule` | `AdditionalUpdates`、本 tick 子步编号 | 行为调度写当前子步 | 把 `extraUpdates + 1` 固定为可测的 step 计划，避免渲染驱动模拟。 |
| `ProjectileTrajectoryState` | 方向、旋转、碰撞/液体策略 | 轨迹系统写位置、速度派生结果 | 纯碰撞 Query 返回接触结果；System 决定状态转换和 command。 |
| `ProjectileOwnerState` | `OwnerEntityRef`、来源种类、归因来源 | 仅 Spawn/反射/显式转移命令写 | 用实体引用而非数组槽位；网络 ID 另由投影映射。 |
| `ProjectileDamageState` | 当前伤害、原始伤害、击退、阵营、伤害类别 | 行为或伤害修正 System 写；Combat 只消费候选 | `ProjectileHitEligibilityQuery` 只返回资格，不能扣血。 |
| `ProjectilePenetrationState` | 剩余额度、最大额度、命中后无害策略 | 命中结果系统唯一写 | 测试 seam 是 `HitAccepted` 事件；无需读取目标生命实现基本额度。 |
| `ProjectileHitImmunityState` | 实例目标冷却、按定义类型冷却策略 | 命中系统写；资格 Query 读 | 每类型静态免疫必须在 `WorldStorage` 的类型键存储中，而非静态进程字段。 |
| `ProjectileLifetimeState` | 剩余 tick、结束原因、召唤持续策略 | `ProjectileLifetimeSystem` 唯一写 despawn command | `TickLifetime` 是确定性纯计算；实体删除只在提交点发生。 |
| `FishingAttemptSnapshot` | 鱼漂位置、液体/水量、玩家装备/区域、世界事件快照 | `FishingEnvironmentQuery` 创建不可变快照 | 规则选择不直接读可变 `Player`/`Main`；可做表驱动纯测试。 |
| `FishingOutcomeQuery` | `FishingAttemptSnapshot`、内容规则、确定性 RNG 端口 | `FishingOutcome` 或无结果 | 只计算，不生成物品；`FishingResolutionSystem` 统一输出 `SpawnItemCommand`。 |
| `GolfBallState` | 击球序号、运动/静止阶段、球实体关系 | `GolfBallSimulationSystem` 写 | 不含镜头位置；得分/跟踪状态与球独立清理。 |
| `GolfRoundState` | 回合/计分记录、当前球引用、时间 | `GolfRoundSystem` 写 | 多球或不同玩家的记录以实体/会话键隔离；镜头读取投影。 |
| `PortalEndpointState` | 端点能力、有效距离/世界限制、可用性 | 门户管理 System 写 | 端点配置与链接关系分离，避免单个状态持有双向一致性。 |
| `PortalLinkState` | 稳定的端点实体引用集合或端点对 | `PortalLinkSystem` 唯一维护 | Link/Unlink command 是唯一写入 seam；删除时由同一系统清理反向关系。 |
| `PortalTraversalCooldownState` | 主体实体引用、下次可穿越 tick 或剩余冷却 | `PortalTraversalSystem` 唯一写 | 旧实现按主体类别保存在两组静态数组；新模型应让冷却跟随被传送主体，且以门户组/端点键消歧。 |
| `LeashAnchorState` | 锚点位置、承载的世界对象身份 | 世界对象/锚点 System 写 | TileEntity/世界坐标通过 adapter 映射，不泄漏到实体核心。 |
| `LeashedEntityState` | 锚点实体引用、当前约束状态 | `LeashConstraintSystem` 写 | 几何约束 Query 纯读；物理修正以命令或运动结果提交。 |
| `LeashBehaviorRef` | 内容定义的行为策略 ID | 行为目录读取 | 不把 20 多个具体生物继承类迁入组件继承树。 |

## 5. 调度、命令与依赖方向

```text
SpawnProjectileCommand / 玩家或 AI 意图
  -> ProjectileSpawnSystem
  -> DefinitionRef + Owner + Behavior + Trajectory + Damage + Penetration + Immunity + Lifetime

每个权威 tick：
  1. ProjectileBehaviorSystem
     -> ProjectileTrajectorySystem
     -> ProjectileHitEligibilityQuery (纯读)
     -> ProjectileHitResolutionSystem -> DamageCandidate / 穿透与免疫更新
     -> CombatAndStatusSystem -> DamageResult
     -> ProjectileLifetimeSystem -> DespawnCommand
  2. Fishing / Golf / Portal / Leash 专用 System
     -> 只读世界、物理和内容快照
     -> SpawnItem / Teleport / Move / Despawn 等 Command
  3. CommitAndIndexSystem
     -> WorldStorage 的唯一实体、Tile、关系与索引写入根
  4. ReplicationProjectionSystem / PersistenceProjectionSystem / ClientPresentationProjection
     -> 只读已提交权威快照
```

关键约束如下：

- `ProjectileBehaviorSystem` 可以提出伤害候选，但不直接写 NPC/Player 生命；伤害、减伤和 Buff 仍由 `CombatAndStatusSystem` 负责。
- `ProjectileHitEligibilityQuery`、`FishingOutcomeQuery`、`PortalTraversalQuery` 和系留的几何资格查询必须无副作用。随机性由显式 `IRandomnessPort`/种子输入提供，不能在 Query 内读全局随机数。
- `PortalTraversalSystem` 必须先验证端点、地图/世界限制、距离、主体可移动性和反环路策略，再提交位置变化；网络包和音效均是提交后的投影。
- 专用 System 的相对顺序不能由目录或文件名表达。若高尔夫球使用投射物轨迹，应在轨迹常规步之前或替代常规步的策略注册中明确声明；`Projectile.UpdatePosition` 已对高尔夫球跳过默认位置推进（`Projectile.cs:17995-18010`），这是需要保留的策略差异。
- `GolfState.TryGetCameraTrackingPosition` 和 `Main` 的相机读取（`GolfState.cs:30-55`, `Main.cs:12382-12390`）属于客户端表现投影，不能倒写高尔夫权威球状态。

## 6. SS14 参考得到的结构性启发

SS14 不是 Terraria 行为的真值来源，仅用于检验拆分是否把不同变更原因硬塞在一起。其可复用的组织原则如下：

| SS14 源码证据 | 可借鉴的结构原则 | 本设计中的落点 |

## 7. 兼容策略、风险与不拆分项

### 7.1 兼容策略

1. 先建立 `ProjectileLegacyAdapter`，只读旧 `Projectile` 并生成新组件快照；不得新旧权威字段双写。
2. 以一个普通命中型投射物建立最小闭环：生成、子步、轨迹、命中资格、伤害候选、穿透、免疫、寿命和销毁。
3. 完成 focused verifier 后，依次迁移水/Tile 碰撞、召唤物、鱼漂、高尔夫、门户、系留实体。每一批只启用一个新权威写者。
4. 协议 `identity/netUpdate/netSpam` 在确认每个字段的服务端/客户端作用域之前保留为外部适配投影；不等同于 ECS `EntityId`，也不等同于数组槽位。

### 7.2 暂不拆分或明确排除

| 项目 | 处理 | 原因 |
| --- | --- | --- |
| `oldPos`、`oldRot`、`oldSpriteDirection` | 表现投影，不进入权威组件 | 旧代码在更新末尾维护轨迹历史；它不应决定碰撞、寿命或伤害。 |
| `Dust`、`SoundEngine`、灯光、`PopupText` | 表现 adapter/事件订阅者 | 网络发送失败、PVS、音频节流都不能反向改玩法。 |
| 全部 AI 样式的逐个迁移 | 不在本报告的首批闭环 | `AI()` 包含大量类型特化；应按行为族逐步登记，而不是建立一个包含所有开关的 `ProjectileBehaviorComponent`。 |
| 高尔夫镜头跟踪 | `ClientPresentationProjection` | `GolfState` 使用 `Main.gameTimeCache` 和 `Main.LocalPlayer`，属于本地视图，不可作为服务器权威记分输入。 |
| 投射物嵌入/抓钩 | 留作后续 `Attachment`/`Leash` 批次 | Version4 抓钩实现为空桩，字段级证据尚不足。 |

### 7.3 行为保持风险

- **子步和寿命耦合**：API 文档明确 `timeLeft` 每次 `Update` 递减，`extraUpdates` 会使其更快耗尽。必须用“模拟子步”而不是仅“逻辑 tick”测试。
- **免疫键范围**：本地目标免疫与按投射物类型静态免疫的键空间不同；迁移时若把后者放到实体组件会失去跨实体共享语义。
- **归属不是实体身份**：`owner` 在旧协议里是玩家槽位，且 `TryGetOwner` 对 NPC/陷阱有特殊语义；必须以 `ProjectileSourceKind` 共同判定。
- **专用规则快照不完整**：高尔夫、鱼漂、门户、抓钩的关键实现缺失或为空桩。它们不能仅依据类型名完成迁移或宣称等价。
- **环境与表现混杂**：旧 `Update` 同时产生 Dust/Sound、调用碰撞、改位置和伤害。迁移时必须把环境读取和权威状态写入与表现事件分离。

## 8. Focused Verifier 计划与本次验证

| 验证目标 | 最小场景 | 断言 |
| --- | --- | --- |
| 定义/实例隔离 | 同一定义生成两个投射物，修改其中一个行为槽位/伤害 | 另一实例和定义目录均不改变。 |
| 子步与寿命 | `AdditionalUpdates = 0, 1, 3` 的相同初始寿命 | 寿命按模拟更新次数减少，`DespawnCommand` 恰在零值产生一次。 |
| 命中资格 | 同一目标连续命中，分别启用本地和按类型免疫 | Query 无写入；冷却期拒绝命中；过期后恢复资格。 |
| 穿透 | 有限、无限、耗尽后无害三种配置 | 命中结果只改 `ProjectilePenetrationState`；无害策略不意外删除实体。 |
| 归属/反射 | 玩家、NPC、陷阱来源与一次反射 | 伤害归因按来源种类解析；反射是显式的所有者变更命令。 |
| 鱼漂 | 一个活跃、同所有者鱼漂与收杆意图 | 玩家查询拒绝重复放竿；结果只经 `FishingResolutionSystem` 产生物品 command。 |
| 高尔夫 | 球在运动、静止、无效所有者三态 | 游戏状态不会由镜头投影写回；球关系失效时回合跟踪清理。 |
| 门户/系留 | 无链接、超距、跨世界、删除端点/锚点 | Query 拒绝无效操作；关系系统清理反向引用；提交前不改变主体位置。 |

本次实际执行的是只读源码审查和报告写入；没有修改 C#、没有运行编译或测试。报告写入后应执行 `git diff --check` 和 Markdown 链接/路径检查。未来实施时，所有 `dotnet` 编译或测试仍必须遵循根 `AGENTS.md`：从仓库根通过 `Build/Tools/Invoke-SerialDotnet.ps1` 串行执行，并先检查没有活动的 `dotnet.exe`/`csc.exe`。
